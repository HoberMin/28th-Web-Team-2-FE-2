## 2. 🔴 핸드오프 전 반드시 수정

### 🔴-1. 하단 GNB — 컴포넌트 3개로 분화 + 활성 탭 불일치

같은 하단 내비게이션이 **서로 다른 컴포넌트 3개**로 존재한다.

| 컴포넌트 이름 | node | 쓰인 화면 | 첫 탭 라벨 |
|---|---|---|---|
| `field/text/nav/gnb` | `223:7003` | 홈, 홈_더보기, 시세 기본, 시세 정렬 | **"탭"** |
| `Frame 2085673353` | — | 시세 검색, 가게 3화면, 찜_가게 | 홈 |
| `Frame 2085673373` | `342:17471` | 찜_야채 | 홈 |

- **라벨이 "탭"** — 플레이스홀더가 그대로 남아 4개 화면에 노출된다. → "홈"
- **아이콘 5개 중 4개가 같은 `icon/home`** — 시세·가게·내 정보가 전부 집 모양이다. 찜(하트)만 다르다. → 시세·가게·내 정보 아이콘 필요
- **활성 탭이 화면과 안 맞는다**
  - 시세 화면(`237:10103`) → 홈 탭이 활성
  - 가게 화면(`319:2924`, `323:7674`) → 홈 탭이 활성
  - 찜 화면(`318:15814`, `318:15555`) → **홈과 찜이 둘 다 활성**으로 보인다
- **컴포넌트 이름 `field/text/nav/gnb`가 오염됐다** — 텍스트 필드에서 복제해 만든 흔적이다. 내비게이션은 `nav/gnb`가 맞다.

→ **1개 컴포넌트로 통합 + `active` variant(홈/시세/가게/찜/내정보 5종)** 로 정리해야 한다. 지금 상태로 넘기면 프론트가 "어느 GNB가 정본인지" 물어보거나 임의로 하나를 고른다.

### 🔴-2. 야채 카드 12개가 detach — 떨어진 것끼리 값이 6가지 어긋난다

`grid/vegetable-item`(`237:11384`) 컴포넌트는 잘 만들어져 있다(`favorite` boolean variant, 토큰 바인딩 정상). 문제는 **각 화면 그리드의 마지막 3칸이 컴포넌트가 아니라 손으로 만든 프레임**이라는 것. 4개 화면 × 3칸 = **12개**.

| 항목 | 컴포넌트 (정상) | detach된 3칸 |
|---|---|---|
| 모서리 반경 | `radius/lg` (12) | **`15.826px` 하드코딩** |
| 이미지 테두리 | `border/img` | **`border/secondary`** |
| 단위 표기 | `/100kg` | **`/1kg`** |
| 이미지 맞춤 | `object-cover` | **`object-contain`** |
| 찜 하트 | 있음 (variant) | **아예 없음** |
| 등락 색 | `trend/down` (파랑) | **`trend/up`(빨강)인데 텍스트는 "(-7.4%)" 하락** |

해당 프레임: `433:25006·25021·25036`(시세 기본) / `433:24797·24812·24827`(시세 검색) / `318:14958·14973·14988`(정렬 시트) / `433:24588·24603·24618`(찜_야채)

→ **12개를 `grid/vegetable-item` 인스턴스로 교체.** 특히 마지막의 색/의미 모순은 프론트가 "상승은 빨강, 하락은 파랑" 규칙을 반대로 구현할 위험이 있다.

### 🔴-3. 더미 숫자가 수학적으로 성립하지 않는다

| 위치 | 표기 | 문제 |
|---|---|---|
| `grid/vegetable-item` | 249,090원 · ▼100,000원 (-7.4%) | 249,090의 7.4%는 약 18,400원이다. 100,000원이면 40% 하락 |
| 홈 `list/lowest-vegetable` | 24,900원 · ▼100,000원 (-7.4%) | **하락액이 현재가보다 크다** |
| detach 카드 | 2,490원 · 200원 (-7.4%) | 직전가 2,690원 기준으로 계산이 맞는다 (이건 정상) |

→ 프론트는 더미 숫자로 "변동률의 기준"을 역추적한다. 지금은 세 곳이 서로 다른 이야기를 해서 **"등락률 = 직전 가격 대비"인지, 기준 기간이 무엇인지 알 수 없다.** 숫자를 한 벌로 맞추고, 아래 ⏸-4에 답을 적어주면 끝난다.

### 🔴-7. 코드에 없는 토큰 4종 (매핑 공백)

Figma에서 쓰고 있지만 `app/globals.css`의 `@theme static` 블록에 **대응 토큰이 없다.** 프론트가 이 값을 넣으려면 하드코딩하거나 멈춰서 물어봐야 한다.

| Figma에서 쓰는 값 | 쓰이는 곳 | 코드 상태 |
|---|---|---|
| `radius/3xl` = 24 | `sheet/store-detail`, `bottom-sheet` 상단 모서리 | **없음** (sm/md/lg/xl/full만 있다) |
| `border/img` = `#0000000d` | 야채 카드 이미지 테두리 | 시맨틱 이름이 없다 (raw `common/black5`만 있음) |
| 시트 그림자 `0 -4px 6px rgba(74,86,103,0.2)` | `sheet/store-detail` | **없음** (`--shadow-floating` 하나뿐, 값이 다르다) |
| 카드 그라디언트 `#f7fff3 → #e8fbd5 → #dbfbb9` | `card/recommended-store` (홈) | **변수에 아예 없다.** 우리 green 팔레트와 다른 계열 |

→ 넷 다 **Figma Variable로 등록**해주는 게 가장 깔끔하다. 특히 그라디언트는 지금 변수 바인딩 없이 raw hex로 칠해져 있어, 나중에 브랜드색을 바꾸면 이 카드만 안 따라온다.

또, 값이 이상한 것 2개:
- `button/circle`의 `radius/full` 폴백이 **749.25px** (다른 곳은 999) — 어딘가에서 스케일이 눌린 흔적
- 하트 아이콘 크기가 **17.25px · 23px** 같은 소수 (원본 24px가 눌린 값)

### 🔴-8. 정렬 시트 — 선택 상태가 컴포넌트에 없다

- `row/sort-option`의 variant가 **`Default` 하나뿐**이다. 화면의 체크 표시(✓)는 컴포넌트 바깥에 손으로 붙여놨다 → `selected` variant 필요
- **트리거 라벨과 선택 상태가 다르다**: 화면 상단은 "가나다순"인데 시트 체크는 "시세보다 저렴한 순"에 있다
- 정렬 옵션 3종은 확정된 것으로 보인다: 가나다순 / 시세보다 저렴한 순 / 최근 제보순

## 4. ⏸ 디자이너 결정이 필요한 것 (= 프론트가 반드시 물어볼 질문)

미리 답을 정해 이 문서에 적어두면, 개발 중 왕복이 사라진다.

### 데이터 표기
1. **단위 기준** — `/100kg`(컴포넌트)과 `/1kg`(detach 카드)이 섞여 있다. 야채마다 단위가 다른가, 전부 통일인가?
2. **필터 칩의 숫자** (전체 46, 감자·뿌리 5, 잎채소 12) — 카테고리별 품목 수인가? 실시간인가?
3. **"8월 4일 기준"** — 시세 기준일. 갱신 주기는? (매일/주간) 오늘 데이터가 없으면 어떻게 표기?
4. **등락률의 기준** — 직전 가격 대비? 전주 대비? 공공 시세 대비? (🔴-3과 연결)
5. **"오늘 / 어제" 배지** — 2일 전 이상은 어떻게 쓰나? ("3일 전", "8/5" 등)
6. **홈 "일주일 간 · 이웃 제보"** — 이 문구가 집계 기간과 출처를 뜻하는 게 맞나?
7. **가게 시트 "최근 제보"가 2건 고정** — 더 많으면 스크롤인가, 상위 N건인가?

### 화면·전환
8. **"가게 상세 보기" CTA의 목적지 화면이 이 섹션에 없다** — 가게 상세 화면은 별도로 있나, 아직 안 그렸나?
9. **찜 해제 시 목록에서 즉시 사라지나?** (사라지면 실수 취소 수단이 필요하다)
10. **홈 "더보기"** — 5건 → 10건까지 확인된다. 10건 이후에도 더보기가 계속 있나? 전체 목록 화면으로 가나?
11. **정렬 시트 닫힘 규칙 (추정: 옵션을 누르면 즉시 적용 + 닫힘 — 가설)** — 딤 탭으로 닫히나? 취소/적용 버튼이 필요한가?
12. **홈 "최근 시세 뉴스"가 632px 폭** (화면 390 초과) → **수평 스크롤 캐러셀로 추정(가설)**. 맞나? 스냅되나? 옆 카드가 살짝 걸쳐 보이나?
13. **시세 화면의 스크롤 영역** — 검색바·필터 칩·정렬줄이 스크롤에 따라 고정되나, 함께 올라가나?

## 5. 🧩 백엔드에 먼저 물어야 할 것

디자인 문제가 아니다. **이 화면들이 성립하려면 서버가 이 데이터를 줘야 한다.** 없으면 화면을 고쳐야 하므로 핸드오프와 동시에 확인하는 게 좋다.

1. **과거 시세 데이터** — 등락률(`-7.4%`)을 계산할 이전 시점 가격
2. **"이웃 제보" 집계** — 제보 원본 + 기간 집계(일주일) + 최저가 산출
3. **"공공 시세보다 저렴한 야채 12가지"** — 공공 시세 기준값과의 비교 연산을 서버가 하나, 프론트가 하나
4. **가게 영업시간·영업중 여부** — 요일별 영업시간 원본이 있나, 서버가 "영업중"을 계산해주나
5. **거리·도보 시간** (`670m`, `도보 10분`) — 서버 계산인가 클라이언트 계산인가
6. **야채 이미지 애셋** — 지금 Figma는 **양파 사진 1장(스크린샷 크롭)을 모든 야채에 재사용**하고 있다("대추방울토마토"·"얼갈이배추"에도 양파 이미지). 품목별 이미지를 서버가 주나, 우리가 준비하나, 저작권은? → **디자인 쪽에서도 결정이 필요한 항목이다**
7. **뉴스 데이터** — 제목·썸네일·날짜·원문 링크의 출처(제휴/크롤링)

## 7. 잘 되어 있는 것 (유지)

핸드오프 관점에서 **이미 프론트가 바로 쓸 수 있는 것들**이다. 위 문제들과 대비되므로 기준점으로 삼으면 좋다.

- **타이포가 전부 Variable로 바인딩돼 있다** — `title/*`·`body/*`·`caption/*` 21종을 벗어난 임의 폰트 크기가 **하나도 없다**. 코드의 `@theme` 토큰과 1:1로 맞는다
- **주요 색이 시맨틱 토큰을 통한다** — `content/*`, `surface/*`, `border/*`, `action-*`, `trend/*` 체계가 일관되게 쓰였다
- **variant 설계가 좋은 컴포넌트들**: `grid/vegetable-item`(favorite) · `filter/chip`(selected/normal) · `tab/bar`(status) · `badge/store-stat`(metric) · `badge/report-date`(date) · `section/recent-report`(state) — 프론트가 그대로 props로 옮길 수 있다
- **등락에 방향 아이콘이 생겼다** (`icon/trend-down` `417:23488`) — 색만으로 상승/하락을 구분하던 문제(WCAG 1.4.1)가 해결됐다. `shared/domain.md`에 "방향 아이콘 미확정"으로 남아 있던 항목은 **이제 갱신 대상**이다
- **긴 텍스트 말줄임·최대폭이 대부분 지정돼 있다** (가게명 228px, 야채명 72px 등)
- 빈 상태 variant를 컴포넌트 레벨에서 만든 사례가 있다 (`section/recent-report`)
