## E. 컴포넌트 이름·구조 정리

컴포넌트 이름은 보통 4단계로 구성돼요: 큰 카테고리(`1 Icon`) → 문서용 껍데기(`sec/button`) → 스펙시트용 껍데기(`spec/button/base`) → 실제 컴포넌트(`button/base`, 카테고리/이름 형태 1개). 8/10에 지적했던 문제들이 지금은 어떻게 됐는지 먼저 확인했어요.

| 8/10에 지적했던 것 | 지금 상태 |
|---|---|
| `spec/circular` 이름이 3단계가 아니라 2단계 | ✅ **해결됨** — `spec/loading/circular`로 바뀜 |
| `spec/vegetable` 2단계 | ✅ **해결됨** — `spec/image/vegetable` + `spec/image/onboarding`으로 분리 |
| `spec/sheet/store-detail` 이름이 중복(내용은 사실 정렬 시트) | ✅ **해결됨** — `spec/sheet/sort`로 이름 바뀜 |
| 이름에 같은 부분이 두 번 반복(`button/base/button/base/...`) | ✅ **이번엔 없음** — 스펙시트 60개·컴포넌트 234개 전부 확인했지만 반복된 이름 없음 |

## 이미 잘 되어 있던 것

- **레이어 순서** — 화면 47개를 다 봤는데, 레이어 패널 순서와 실제로 화면에 보이는 순서가 어긋난 곳은 없었어요.
- **구조용 프레임 이름** — 부모-자식 관계를 이어 붙이는 이름 규칙이 잘 지켜지고 있었어요(예: `가격그래프` → `가격그래프-그룹` → `가격그래프-툴팁-라벨`까지 세세하게).
- **화면 이름** — 47개 모두 정해진 형식(`F0X_화면명`)을 잘 따르고 있었어요. 페이지 목록 문서에 없는 화면 1개(`F03_가게상세_더보기_누름`)만 F섹션 19번에 올렸어요.
- **컴포넌트 4단계 구조** — 스펙시트 60개 중 58개, 컴포넌트 이름 234개 전부 규칙을 잘 지키고 있었어요.
- **이름 복붙 실수** — 이전에 있었던, 이름이 중복으로 붙는 문제는 이번엔 하나도 없었어요.

## 이번엔 못 본 부분

- 그림(이미지)이나 아이콘 안쪽 세부 요소의 이름은 검사하지 않았어요 — 원래 검사 대상이 아니에요.
- 컴포넌트 안에 또 다른 컴포넌트가 겹쳐 들어있는 경우 11건은 화면에서는 이름을 못 고쳐요. 그중 1건만 원본에서 고쳤고(13번), 나머지는 어느 원본을 고쳐야 화면에 반영되는지 이번엔 못 찾았어요.
- 색이 직접 지정된 자동생성 이름 노드 16개는 정확한 위치를 못 찾았어요.
- 글자 스타일이나 여백이 스타일/변수에 연결돼 있는지는 이번엔 안 봤고, 색상만 확인했어요.
- `장보고 Design` 파일 쪽 사본은 화면 이름 목록만 비교했고, 안쪽까지는 못 봤어요. 정본이 정해졌으니 다음엔 그쪽도 같은 기준으로 봐야 해요.

## 정리

**고친 것**: 자동으로 붙은 이름 128개를 원래 이름으로 되돌렸어요. 라이브러리 원본에 이미 있던 이름으로 되돌린 거라 추측 없이 확실한 것만 고쳤고, 디자인 자체는 안 바뀌었어요.

**안 고친 것**: 크기 문제(8종, 131곳)·색상 문제(5종)·연결 끊김(18곳)·컴포넌트 이름/구조(9건)는 목록으로만 정리했어요. 디자이너 확인이 필요한 부분이라 임의로 정하지 않았어요.

**정본 확정 (8/19)**: 17·18번 — 작업실 쪽이 기준이 되는 원본이에요. `(공유) Component`·공유 `화면` 문서·`장보고 Design` 사본은 오래된 버전이라 지금은 프론트엔드에 전달하지 않아요. 사본 정리는 다음 조사에서 진행할게요.
