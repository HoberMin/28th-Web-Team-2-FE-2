# F05-3 마이페이지 · 내 제보

경로 — `/prototype/mypage/reports`

> 오타 제보를 되돌릴 수 있는 유일한 자리. 시스템은 이상치를 흐리게 표시만 하고 본인은 못 고치는 구멍을 막는다.

> 「시세만 봄」 배지는 없앴다. 구매 여부를 더 이상 묻지 않으므로 옛 제보에만 붙어 기준이 둘로 보인다.
> 데모용 시드 제보는 저장소에 없어 수정·삭제 대상이 아니다 — 그런 줄에는 `⋯`가 아예 없다.

#### 정책

- 스와이프 삭제를 쓰지 않는다. 있는 줄 모르면 영원히 못 찾고 타깃 연령대에 특히 불리하다. 명시적 메뉴로 노출한다
- 수정은 제보 폼 전체로 되돌리지 않고 양·가격만 고치는 가벼운 시트로 처리한다. 품목·가게·동네는 바꾸지 않는다
- 삭제는 확인 단계를 둔다
- 수정은 덮어쓰기다. 이력을 남기지 않는다. 수정은 대부분 오타 정정이라 틀린 값을 보존할 이유가 없다
- 눌러도 안 되는 버튼은 보여주지 않는다. 수정할 수 없는 항목은 `⋯` 메뉴 자체를 숨긴다
- 시세 비교 기준은 서버가 내려준 오늘 시세다. 화면마다 기준이 갈리지 않게 홈·시세 화면과 같은 값을 쓴다

#### Description

1. 앱바 — "내 제보". 뒤로가기는 마이페이지
2. **목록** — 내가 올린 제보만
	- 2-1) 품목명
	- 2-2) 그 아래 제보일 · 동네
	- 2-3) 우측에 1kg 환산가 "{금액}원 /1kg"
	- 2-4) 그 아래 오늘 시세와의 차이 — "오늘 시세보다 {금액}원 저렴" / "오늘 시세보다 {금액}원 비쌈". 방향 기호를 함께 붙인다. 차이가 없거나 오늘 시세가 없는 품목(비수기 등)은 줄 자체를 그리지 않는다
	- 2-5) 우측 끝 `⋯`. 이름표로 "{품목} 제보 수정·삭제"를 전달한다
3. **`⋯` 메뉴 시트** — 「제보 관리」. 수정 / 삭제
4. **수정 시트** — "{품목} 제보 수정". 양·가격 두 칸만. 둘 다 0보다 커야 「저장」이 열린다. 저장하면 목록에 바로 반영
5. **삭제 확인 시트** — "이 제보를 삭제할까요?" / "삭제하면 되돌릴 수 없어요." → 「삭제」·「취소」

#### 상태 3종

| 상태 | 처리 |
|---|---|
| 로딩 | 없음 |
| 에러 | 수정 시 양·가격이 0 이하면 「저장」 비활성 |
| 빈 | "아직 제보한 내역이 없어요. 야채 시세 화면에서 실제 가격을 제보해 보세요." |
