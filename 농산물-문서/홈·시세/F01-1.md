# F01-1 야채 시세 [GNB]

경로 — `/prototype/vegetables`

> 46종 전체를 검색·필터·정렬로 훑는 화면. 품목 하나의 상세는 F03이다.

> 시세·등락은 서버(KAMIS)에서 조립해 props로 내려온다. 검색·필터·정렬만 클라이언트가 맡는다.

#### 정책

- 검색어가 있으면 종류 필터를 무시한다. 이름을 아는 사람은 목적지가 이미 정해져 있고, 두 필터가 동시에 걸리면 결과가 왜 비었는지 알 수 없다
- 유사 품목은 화면에서 합치지 않는다. 애호박과 쥬키니, 대파와 쪽파, 적상추와 청상추, 방울토마토와 대추방울토마토, 고춧가루 국산과 중국산
- 비수기 품목은 가격 대신 계절 문구를 보여준다. 값이 없는 게 정상인 품목이 있다
- 시세가 대체값으로 채워졌으면 화면에 그 사실을 밝힌다. 진짜 시세인지는 판단의 전제라 숨기면 안 된다. 46종 중 하나라도 폴백이면 표기한다
- 앱바가 이미 "야채 시세"를 달고 있어 본문에서 같은 말을 헤더로 반복하지 않는다

#### Description

1. 앱바 — "야채 시세". 탭 루트라 뒤로가기가 없다
2. **검색 필드** — 라벨 「야채 검색」을 눈에 보이게 단다. placeholder만 두면 입력 후 이 칸의 용도가 화면에서 사라진다
	- 2-1) placeholder "야채 이름 또는 초성으로 검색 (예: ㄱㅈ)"
	- 2-2) 초성만 입력하면 초성 매칭, 아니면 이름 부분 매칭
	- 2-3) 검색 중에는 화면에 보이지 않는 「검색 결과」 헤딩을 남긴다. 캡션 하나로 합쳤어도 헤딩으로 건너뛰는 사용자에게는 지점이 필요하다
3. **정렬 버튼** — 「정렬 · {현재값}」. 누르면 「정렬」 바텀시트에서 가나다순 / 싼 순 / 많이 내린 순. 고른 항목에 체크 표시
	- 3-1) 종류 칩보다 위계를 낮춘다. 둘 다 칩이면 무엇이 필터고 무엇이 정렬인지 구분이 안 간다
	- 3-2) 정렬을 바꾸면 목록이 다시 12종으로 접힌다
4. **기준 캡션** — 정렬 버튼과 같은 줄 오른쪽. "N종 · {M}월 {D}일 기준". 대체값이면 "· 예시 데이터"를 붙인다. 검색 중에는 "‘{검색어}’ 검색 결과 · N종"
5. **종류 칩** — 전체 / 감자·뿌리 / 잎채소 / 열매채소 / 고추 / 양념 / 버섯 / 과채. 가로 스크롤. 검색 중에는 숨긴다
	- 5-1) 칩마다 그 종류의 품목 수를 붙인다(예: 「잎채소 12」). 누르기 전에 몇 개나 있는지 알 수 있어야 헛걸음이 줄어든다. 개수는 지금 데이터에서 직접 센다
6. **야채 그리드** — 3열. 썸네일 / 이름 / 가격 / 등락
	- 6-1) 기본 12종. 「더보기 · N종 더 보기」로 46종 전체
	- 6-2) 검색 중에는 자르지 않는다. 찾는 게 목적인 화면에서 페이지네이션은 방해다
	- 6-3) 비수기 품목은 가격 자리에 계절 문구(품목에 문구가 없으면 "지금은 비수기")
	- 6-4) 가격에는 기준 단위를 붙인다(예: "3,200원 /kg"). 46종의 단위가 kg·g·개·포기로 섞여 있어 값만 두면 품목끼리 비교가 성립하지 않는다
	- 6-5) 등락은 금액과 퍼센트를 함께 준다(예: "700원 (-5.9%)"). 퍼센트만 보여주면 원래 가격을 알아야 얼마인지 나온다
	- 6-6) 등락 색은 상승 빨강 · 하락 초록(구매자 기준). 화살표·색만으로 전달하지 않고 스크린리더용 문구를 따로 둔다
	- 6-7) 0.5% 미만 변화는 변동 없음으로 보고 "-" 한 글자만 둔다. 매일 소액에 화살표가 뒤집히면 신호가 아니라 잡음이다
