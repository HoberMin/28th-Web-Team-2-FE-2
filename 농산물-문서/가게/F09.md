# F09 가게 상세

경로 — `/prototype/store/{가게명}`

> "이 가게는 뭐가 싸고 뭐가 비싼가"에 한 화면으로 답한다.

> 섹션 순서는 사진 → 요약 → 위치 → 제보된 가격 → 동네 댓글이고, 하단에 「이 가게에 제보하기」가 고정된다.
> 지도는 실제 Kakao Maps SDK다(가게 탭 F07의 가짜 지도와 다르다). 다만 좌표·주소는 동 중심 + 가게명 해시로 만든 값이라 실측이 아니다.
> 「단골」은 「찜」으로 용어가 통일됐다. 가게 신선도 후기는 별도 섹션이 없다 — 개수는 요약 카드에, 한마디는 동네 댓글에 섞인다.

#### 정책

- 사진이 최상단이다. 목록·지도에서 이름 한 줄이던 가게를 찾아가는 사람은 간판을 보고 "여기가 거기"를 확인하는데, 첫 화면이 숫자부터면 그 확인이 안 된다. 프로토타입에는 실사진이 없어 가게명 해시로 색을 고른 결정적 플레이스홀더를 둔다
- 위치를 가격 목록보다 먼저 둔다. 갈 만한 거리인지가 정해져야 가격을 볼 이유가 생긴다
- 제보가 하나도 없는 가게여도 위치는 보여준다. 그 화면에서 유일하게 확실한 정보다
- 같은 품목은 최신 1건을 대표로 쓴다. 가격은 시간에 민감하다
- 정렬은 시세 대비 싼 품목 순. 방문할 이유가 먼저 읽혀야 한다. 이상치는 어느 탭에서든 맨 아래 — 값이 의심스러운 줄이 첫 줄에 오면 목록 전체가 의심받는다
- 싼 품목과 비싼 품목을 한 목록에 섞지 않고 2탭으로 나눈다. 이 화면에 오는 이유가 "여기 뭐가 싸냐"라서 그 답만 먼저 볼 수 있어야 한다. 탭 라벨에 개수를 붙여 누르기 전에 어느 쪽이 두꺼운지 보이게 한다
- 시세 비교가 불가능한 품목은 「비싸요」 쪽에 두되 차이 줄을 그리지 않는다. 비교값이 없는 것을 "비쌈"으로 단정하지 않는다
- 섹션 이름은 「이 가게에 제보된 가격」이다. 가게가 게시한 공식 가격표가 아니라 이웃이 보고 남긴 값이라, 이름이 출처를 숨기면 틀린 값의 책임이 가게로 간다
- 결론(요약)이 섹션 제목보다 위계가 커야 한다. 목록 라벨이 결론보다 크면 위계가 뒤집힌다
- 교차검증 배지는 무채색이다. 초록은 「싸다」 전용이라 신뢰 신호에 쓰면 뜻이 겹친다
- 후기용 목록을 따로 만들지 않는다. 후기 한마디를 댓글과 시간순으로 섞는다 — 비슷한 목록이 둘이 되는 걸 막는다
- 댓글 작성은 지금 내 동네 제보가 있는 가게에만 열린다. 그 외에는 읽기만 가능하다
- 뒤로가기는 온 길로 돌아간다. 여러 경로에서 들어오는 화면이라 목적지를 고정하면 오작동한다

#### Description

1. 앱바 — 가게명. 우측에 찜 하트 버튼
	- 1-1) 찜을 켜고 끄면 스크린리더에 "{가게명} 찜했어요 / {가게명} 찜을 해제했어요"를 알린다. 아이콘 변화만으로는 아무것도 안 읽힌다
	- 1-2) 낭독 문구는 "{가게명} 찜하기 / {가게명} 찜 해제", 상태는 `aria-pressed`로도 전달한다
2. **가게 사진** — 화면 폭을 꽉 채운 플레이스홀더. 가게 아이콘 + "가게 사진 준비 중". 사진이 없다는 걸 숨기지 않는다(회색 박스만 두면 로딩 실패로 읽힌다)
3. **요약 카드** — 이 화면의 결론
	- 3-1) 싼 품목이 있으면 "N개 품목이 오늘 공공 시세보다 싸요", 없으면 "이웃 제보 N개 품목"
	- 3-2) 그 아래 "{동네} · 가장 최근 제보 {오늘/어제/N일 전}". 목록이 싼 순으로 정렬돼 있어 첫 줄이 최신이 아니므로 실제 제보 시점이 가장 이른 것을 따로 찾는다
	- 3-3) 제보가 1건뿐이면 " · 제보가 1건뿐이라 참고만 해주세요"를 잇는다. 근거가 얇을 때 단언하지 않는다
	- 3-4) 후기가 있으면 "가게 후기 좋아요 N · 보통 N · 별로 N" (F04-3에서 받은 값)
4. **위치** — 제목 「위치」. 지도(Kakao SDK) + 주소 + "내 위치에서 {거리} · 걸어서 {N}분"
	- 4-1) 앱키(`NEXT_PUBLIC_KAKAO_JS_KEY`)가 없거나 SDK 로드가 실패하면 빈 영역 대신 회색 박스 + "지도를 표시할 수 없어요". 주소·거리는 그대로 남아 화면이 깨지지 않는다
	- 4-2) 지도는 보조 표현이라 낭독에서 제외하고, 로딩·실패만 낭독한다 — "지도를 불러오는 중이에요" / "지도를 불러오지 못했어요. 아래 주소로 확인해 주세요."
	- 4-3) 주소와 거리는 동 중심 + 가게명 해시로 만든 값이다. 제보 폼이 가게명만 받아 좌표가 없다 — 실서비스에서 장소 검색 좌표가 들어오면 이 계산만 교체된다
5. **이 가게에 제보된 가격**
	- 5-1) 「저렴해요 N」 / 「비싸요 N」 2탭
	- 5-2) 줄마다 썸네일 / 품목명 / 제보 시점 태그 / 우측에 "{가격}원 /{단위}"와 시세 대비 차이("{금액}원 싸요 (N%)" · 「시세와 같아요」)
	- 5-3) 같은 가게·같은 품목 제보가 2건 이상이면 품목명 옆에 「이웃 N명 확인」 배지
	- 5-4) 이상치는 "확인 필요 · 시세와 차이가 너무 커서 오타일 수 있어요"를 붙이고 맨 아래로. 지우지는 않는다
	- 5-5) 줄을 누르면 그 품목의 시세 화면(F03)
6. **동네 댓글** — 닉네임 + 내용 + 상대 시점("3일 전")
	- 6-1) 가게 후기 한마디는 작성자 자리에 「이웃 후기」 + 등급 배지(좋아요/보통/별로)로 같은 목록에 섞인다
	- 6-2) 등록하면 "댓글을 등록했어요"를 낭독한다
	- 6-3) 이 동네 제보가 없는 가게면 입력 칸 대신 "이 동네 제보가 없는 가게라 댓글은 읽기만 가능해요."
	- 6-4) 한글 입력 중 엔터로 미완성 글자가 제출되지 않게 한다
7. **「이 가게에 제보하기」** — 하단 고정. 가게를 이미 특정한 상태라 폼의 가게 선택을 건너뛴다(가게명 프리필)

제보가 0건인 가게는 3·5를 그리지 않고 "아직 이 가게 제보가 없어요 / 다녀오셨다면 가격을 남겨주세요. 이웃이 헛걸음하지 않아요." + (후기가 있으면) 후기 개수 한 줄 + 위치만 남긴다. 댓글과 하단 CTA는 그대로 있다.

#### 없는 가게로 들어온 경우

URL을 직접 조작해 들어올 수 있다. 아는 가게 목록·찜·내 제보 어디에도 없는 이름이면 앱바를 「가게 정보」로 바꾸고 "찾을 수 없는 가게예요 / 주소가 바뀌었거나 없는 가게일 수 있어요." + 「가게 둘러보기」(F07).

#### 상태 3종

| 상태 | 처리 |
|---|---|
| 로딩 | 제보·댓글이 localStorage라 서버 스냅샷은 항상 비어 있다. 하이드레이션 전에는 앱바 + 자리표시 3줄만 그린다. 그대로 그리면 "제보 없음"·"댓글 없음"이 한 틱 깜빡였다 목록으로 바뀐다 |
| 에러 | 없는 가게 — 위 「없는 가게로 들어온 경우」. 저장소 읽기 실패는 빈 상태와 구분해 "댓글을 불러오지 못했어요. 새로고침해 주세요." |
| 빈 | 제보 0건이어도 위치·댓글·CTA는 남긴다. 댓글 0건이면 "아직 댓글이 없어요.", 탭이 비면 "공공 시세보다 저렴한 품목이 아직 없어요" / "공공 시세보다 비싼 품목은 없어요" |

#### 화면 전환

- 진입 — F07 지도 시트의 「가게 상세 보기」, 홈 「이 가게 어때요?」 카드, 제보 목록의 가게명, 찜 탭 「가게」 목록(F05-5)
- 품목 → F03 / 제보 CTA → F04-2(가게명 프리필) / 없는 가게 → F07 / 뒤로가기 → 온 길
