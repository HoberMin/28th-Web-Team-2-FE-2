## 1. 품목 카테고리에 「깨·견과류」 추가

- **대상**: `GET /api/v1/items` 의 `category` enum
- **현재**: `ROOT_VEGETABLES` · `LEAFY_GREENS` · `FRUITING_VEGETABLES` · `PEPPERS` · `SEASONINGS` · `MUSHROOMS` · `FRUITS` (7종)
- **필요**: 위 7종 + **깨·견과류** (총 8종)

**왜 필요한가**
디자인 최종본의 카테고리 목록이 8종입니다. 지금 참깨·땅콩이 `SEASONINGS`(마늘·파·생강)에 들어가 있어 화면에서 잘못된 카테고리로 노출됩니다.

**요청**: enum 추가 + 해당 품목 재분류

---

## 2. 품목 목록 정렬 2종 추가

- **대상**: `GET /api/v1/items` 의 `sort` enum
- **현재**: `NAME_ASC` · `PRICE_ASC` · `PRICE_DESC`
- **필요**:
  - **시세보다 저렴한 순** (공공시세 대비 할인율)
  - **최근 제보순**

**왜 필요한가**
디자인의 정렬 시트가 「가나다순 / 시세보다 저렴한 순 / 최근 제보순」 3종입니다. 가나다순은 `NAME_ASC`로 되지만 나머지 2종이 없어 화면 라벨을 시안대로 바꿀 수 없습니다. 라벨만 바꾸면 실제 동작과 어긋나서 그대로 두고 있습니다.

---

## 3. 「오늘 제보된 품목」 수 필드 추가

- **대상**: `StoreDetailResponse` (`GET /api/v1/stores/{storeId}`)
- **현재**: `totalReportedItemCount` (누적)
- **필요**: 오늘 기준 제보 품목 수 (예: `todayReportedItemCount`)

**왜 필요한가**
가게 상세와 지도 가게 시트의 배지 2개 중 하나가 「오늘 제보된 품목 N」입니다. 누적값으로는 계산할 수 없습니다.

**참고**: 같은 화면의 영업상태 · 오늘 영업시간 · 도보시간 · 저렴한 야채 수는 이미 응답에 있어서 **프론트에서 붙이면 됩니다.** 이 필드만 없습니다.

---

## 4. 제보 `unit` 제약 확인 — 답변 필요

- **대상**: `POST /api/v1/items/{itemId}/reports` 의 `unit`

**상황**
스펙상 `unit`은 자유 문자열(`maxLength: 20`)인데, 일치 요구가 `AnalyzedItem.unit`의 **설명 문구에만** 적혀 있습니다("제보 저장 시 unit으로 보낼 값. 서버가 이 문자열과의 일치를 요구한다"). 이 때문에 프론트에서 단위 선택 UI를 제거했고, 디자인팀이 다시 넣어달라고 요청한 상태입니다.

**질문**

| # | 질문 |
|:--:|---|
| 4-1 | 품목 `defaultUnit`과 **다른** `unit`으로 저장이 되나요? (`defaultUnit`이 `"1kg"`인 품목에 `"개"`로 제보) |
| 4-2 | 저장된다면 조회 시 가격 비교를 **서버가 환산해서** 주나요, 아니면 단위가 섞인 채 내려오나요? |
| 4-3 | 표기 형식은 어느 쪽인가요? 디자인 옵션은 `kg` / `g` / `개` / `포기` 인데 `defaultUnit`은 `"1kg"` / `"100g"` / `"1개"` 형식입니다 |

**이렇게 답해주시면 됩니다**
```
4-1. 가능 / 불가능
4-2. (가능이면) 서버 환산 / 원본 그대로
4-3. "1kg" 형식 / "kg" 형식
```
