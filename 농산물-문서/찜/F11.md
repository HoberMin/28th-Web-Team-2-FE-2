# F11 찜 [GNB]

경로 — `/prototype/favorites`

> 관심 품목과 찜한 가게로 되돌아오는 상시 경로. 반복 구매가 타깃의 특성인데 이전엔 마이페이지 2단 깊이에 묻혀 있었다.

> 화면 ID는 임시 배정(가설)이다
> GNB 3번째 자리의 랭킹 탭을 대체해 신설됐다. 두 목록은 원래 마이페이지 하위 화면 둘(찜한 야채·찜한 가게)이었다.
> 「가게」 세그먼트는 F05-5와 같은 본문 컴포넌트를 쓴다 — **같은 목록·같은 해제 동작이 두 경로에 중복으로 존재한다.**

#### 정책

- 두 목록을 하나로 합치지 않고 세그먼트로 나눈다. 품목 그리드와 가게 리스트는 성격이 달라 한 목록에 섞으면 무엇을 보는 화면인지 흐려진다
- 처음 열면 「야채」다. 찜의 기본 축은 품목이다
- 야채는 리스트가 아니라 그리드다. 리스트로는 한 화면에 몇 개뿐이라 "내가 찜한 것들"이 한눈에 안 들어온다
- 카드 모양은 야채시세 탭(F01-1)과 같게 맞춘다. 두 화면을 오갈 때 같은 것을 같은 모양으로 본다
- 시세는 서버가 내려준 오늘 시세를 그대로 쓴다. 화면이 따로 계산하면 기준이 갈린다
- 찜 = 구독이다. 별도 등록 없이 알림 대상이 된다(F05-1)
- 해제는 목록 안에서 끝난다. 상세로 들어갔다 나오게 만들지 않는다

#### Description

1. 앱바 — "찜". GNB 탭 루트라 뒤로가기 없음
2. **세그먼트** — 「야채」 / 「가게」. 이름표로 "찜 목록 종류"를 전달한다
3. **「야채」** — 3열 그리드
	- 3-1) 카드마다 야채 일러스트 / 품목명 / 오늘 시세 "{금액}원"
	- 3-2) 오늘 시세가 없으면 가격 대신 계절 문구, 없으면 "지금은 비수기"
	- 3-3) 카드 오른쪽 위에 하트. 여기서 바로 해제한다. 카드 링크와 겹치지 않게 얹는다
	- 3-4) 카드를 누르면 F03
4. **「가게」** — F05-5와 같은 목록
	- 4-1) 줄마다 가게명 + 해제 버튼. 이름표는 "{가게명} 찜 해제"
	- 4-2) 가게명을 누르면 F09

#### 상태 3종

| 상태 | 처리 |
|---|---|
| 로딩 | 없음 — 목록은 저장소를 바로 읽고, 첫 방문에도 시드가 채워져 깜빡임이 없다 |
| 에러 | 없음. 시세를 못 받은 품목은 가격 대신 계절 문구로 떨어진다 |
| 빈 | 야채 — "아직 찜한 야채가 없어요. 관심 야채에 하트를 눌러 보세요." / 가게 — "아직 찜한 가게가 없어요. 가게 상세에서 하트를 누르면 여기에 모여요." |

#### 화면 전환

- 진입 — GNB 「찜」
- 야채 카드 → F03
- 가게 줄 → F09
- 찜 등록 지점 — 야채는 시세 상세(F03) 앱바 하트, 가게는 가게 상세(F09) 앱바 하트와 동네 가게(F07) 지도의 가게 시트 하트
