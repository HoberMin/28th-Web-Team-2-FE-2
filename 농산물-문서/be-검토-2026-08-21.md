## 1. 🔴 `GET /api/v1/regions/search` — 흔한 검색어가 전부 502

### 증상

온보딩에서 **동네를 고를 수 없습니다.**

```
GET /api/v1/regions/search?keyword=서초
→ 502 {"code":"EXTERNAL_API_ERROR","message":"외부 API 호출 중 오류가 발생했습니다."}
```

### 재현 (라이브 실측, 2026-08-21)

| keyword | 결과 |
|---|---|
| `신촌`(1건) · `판교`(2건) | 200 ✅ 좌표까지 정상 |
| `삼성` · `홍대` · `123` (0건) | 200 ✅ 빈 배열 |
| **`서초` · `역삼` · `대치` · `삼성동`** | **502** ❌ |
| **`강남` · `강남구` · `종로` · `부산` · `제주`** | **502** ❌ |
| `동` · `가` · `abc` | 400 `INVALID_PARAMETER_ERROR` (정상) |

**후보가 여러 건 잡히는 검색어가 전부 실패**합니다. 0건이거나 1~2건일 때만 통과합니다.

### 원인 (코드로 확정)

`external/kakao-client/.../feign/KakaoResponseDecoder.java`

```java
private void validateDocuments(final JsonNode documents, final Type type) {
    documents.forEach(document -> validateDocument(document, type));   // ← 배열 전체를 엄격 검증
}

private void validateAddress(final JsonNode address) {
    ...
    final JsonNode detail = address.get("address");
    if (detail == null || !detail.isObject()) {
        throw externalApiException();                    // ← :135  502
    }
    requireNonBlankText(detail, "region_3depth_name");   // ← :141  502
}
```

카카오 `/v2/local/search/address.json`은 문서마다 `address`(지번)와 `road_address`(도로명)를
주는데 **둘 중 하나가 `null`일 수 있습니다.** 도로명으로만 매칭된 결과는 `address: null`이고,
시·구 단위 결과는 `region_3depth_name`이 빈 문자열입니다.

**둘 다 카카오의 정상 응답인데 디코더가 외부 API 장애로 오인**합니다. 게다가 배열 전체를
검사해서 **`SEARCH_SIZE = 30`건 중 한 건만 어긋나도 응답 전체가 502**가 됩니다.
검색어가 흔할수록 이런 문서가 섞일 확률이 올라가는 것이 위 재현표의 패턴입니다.

> **가설 표시**: "서초·역삼은 도로명 전용 항목 때문", "종로·부산은 `region_3depth_name`이 빈 값
> 때문"이라는 **건별 귀속은 가설**입니다(API 키가 없어 카카오 원본 응답을 직접 못 봤습니다).
> **디코더가 두 경우를 502로 만든다는 것과 한 건이 전체를 죽인다는 것은 코드로 확정**입니다.

### 이미 있는 방어가 무력화돼 있습니다

`KakaoRegionSearchAdapter`에는 이상 항목을 건너뛰는 방어가 이미 있습니다.

```java
final String bCode = address.bCode();
if (bCode.isBlank()) {
    return;                    // 쓸 수 없는 항목은 건너뛴다 — 의도가 맞습니다
}
```

그런데 **디코더가 그 앞에서 죽어** 여기까지 도달하지 못합니다. 어댑터의 의도(걸러 쓴다)와
디코더의 동작(하나라도 이상하면 전부 버린다)이 어긋난 상태입니다.

### 왜 테스트에 안 잡혔나

- `KakaoResponseDecoderTest`(143줄)에 **`address: null` 케이스가 없습니다.**
- `KakaoRegionSearchAdapterTest`는 `bCode` 빈 문자열을 커버하지만 **디코더를 통과한 뒤**의
  이야기라 이 결함을 잡지 못합니다.

### 제안하는 수정

**"카카오의 정상 형태 차이"만 건너뛰고, 진짜 이상은 그대로 502**로 둡니다.

- `address`가 없거나 `region_3depth_name`이 빈 문서 → 법정동 정보가 없으므로 **그 문서만 버림**
- 좌표 범위 이상 · 필수 필드 누락 · 빈 객체(`{}`) → **기존대로 502**
- 응답 구조 자체가 깨진 경우 → `validateEnvelope`가 **기존대로 502**
- **주소 검색에만 적용.** `coord2regioncode`와 장소 검색은 결과 형태가 균일해 필수 필드 누락이
  곧 이상 신호이므로 건드리지 않았습니다

```java
private JsonNode usableDocuments(final JsonNode documents, final Type type) {
    if (type != KakaoAddressSearchResult.class) {
        documents.forEach(document -> validateDocument(document, type));
        return documents;
    }
    final var usable = objectMapper.createArrayNode();
    documents.forEach(document -> {
        if (!carriesLegalRegion(document)) {
            return;                        // 카카오의 정상 변형 — 버리고 계속
        }
        validateDocument(document, type);  // 남은 문서는 예전처럼 엄격히
        usable.add(document);
    });
    return usable;
}
```

> **판단 하나 확인 부탁드립니다**: 이 수정은 30건 중 쓸 수 있는 게 하나도 없으면 **빈 배열 200**을

## 3. 🟡 `regionId` 타입이 엔드포인트마다 다릅니다

| 엔드포인트 | `regionId` |
|---|---|
| `/regions/search` | `"1141011400"` **문자열** |
| `/regions/{id}/items/{id}/reports` | `"1168010600"` **문자열** |
| **`/regions/nearby`** | `1168010600` **숫자** |

법정동 코드는 **앞자리 0이 유실되면 안 되는 코드값**입니다(예: `0111010100`).
숫자로 오면 프론트에서 10자리로 `padStart`해 복원하는데, **자릿수 고정을 가정한 우회**라
불안합니다. `/regions/nearby`도 문자열로 통일해 주실 수 있을까요?

## 4. 🟡 `/regions/nearby`만 좌표를 안 내려줍니다

```
/regions/search → {"regionId":"...", "regionName":"...", "latitude":37.56, "longitude":126.93}
/regions/nearby → {"regionId":1168010600, "regionName":"강남구 대치동"}          ← 좌표 없음
```

같은 "지역"인데 응답 모양이 다릅니다. 프론트는 좌표가 필요해서 `nearby`로 고른 지역은
**이름으로 `search`를 다시 호출해 좌표를 복구**하고 있었습니다. §1의 502를 실제로 밟은 경로가
이것입니다 — **이 비대칭이 §1의 폭발 반경을 키웠습니다.**

`nearby`도 좌표를 함께 주시면 이 재검색이 통째로 사라집니다.
(그때까지는 프론트에서 조회에 쓴 사용자 좌표를 얹어 임시로 우회해 뒀습니다 — §6)

### 동종 결함 점검

§1과 같은 **"한 건 어긋나면 전체 502"** 구조가 `validatePlace`(장소 검색)와
`validateRegion`(좌표→행정구역)에도 있습니다. 다만 **지금은 문제가 안 됩니다**:

- 좌표→행정구역은 결과가 1~2건이고 형태가 균일합니다
- 장소 검색의 `phone`·`road_address_name`은 `requireText`라 빈 문자열을 통과시킵니다
  (`requireNonBlankText`가 아닙니다 — 다행입니다)

**지금 고칠 결함은 아니라고 봅니다.** 다만 카카오가 형태를 바꾸면 같은 방식으로 터질 수 있는
자리라 적어 둡니다.
