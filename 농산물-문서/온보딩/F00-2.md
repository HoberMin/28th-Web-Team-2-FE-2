# F00-2 온보딩 · 지역 선택

경로 — `/prototype/onboarding` *(2026-08-05 코드 기준 재검토)*

> F00-1과 라우트가 하나다. 닉네임 단계를 통과하면(비회원은 곧바로) 이 단계가 화면 안에서 나타난다.
> 선택 UI(`_components/region-picker.tsx`)는 세 곳이 공유한다. 온보딩(전체 화면) / 홈 위치 라벨 시트(F01) / 내 정보 동네 관리(F05-1). 한 곳을 고치면 세 곳이 같이 바뀐다.

#### 정책

- 동네 인증 없음. 실제 거주지가 아니어도 아무 동네나 고를 수 있다
- 동네는 한 번에 하나만 활성. 등록은 최대 3개까지고, 넘치면 가장 오래 전에 등록한 것이 밀려난다. 온보딩에서 고른 동네가 첫 등록이 된다
- 로그인 여부와 무관하게 이 단계는 거친다

#### Description

1. 뒤로 가기 — 헤더 왼쪽. 회원은 닉네임 단계로, 비회원은 소개 화면(F00-0)으로 돌아간다. 입력한 닉네임은 유지된다
2. 제목 — "평소 어디에서 야채를 구매하나요?"
3. **「현재 위치로 찾기」**
	- 3-1) 측위 중 라벨 "위치 확인 중…" + 버튼 비활성. 라벨·안내 변화는 스크린리더에 바로 읽힌다
	- 3-2) 성공하면 그 동네를 바로 채택해 홈으로 넘어간다. 목록만 다시 정렬되고 화면이 안 넘어가면 반응이 없는 걸로 읽힌다
	- 3-3) 실패(권한 거부·타임아웃·미지원·변환 실패)는 버튼 아래 한 줄 — "위치를 확인할 수 없어요. 아래에서 동네를 검색해 주세요". 에러 화면을 띄우지 않고 검색 경로에 조용히 남는다
4. **검색 필드** — placeholder "동 단위로 검색". 부분일치. 검색어를 바꾸면 목록 스크롤이 맨 위로
5. 섹션 라벨 — 검색어 없을 때만
	- 5-1) 위치를 알면 "지금 있는 동네"
	- 5-2) 모르면 "동네 추천" — 온보딩 첫 진입은 항상 이쪽이다. 기준 지역(삼성동)에서 가까운 순으로 조용히 폴백하기 때문에 "지금 있는 동네"라고 말하지 않는다
6. **지역 목록** — 검색어 없으면 기준점에서 가까운 4개, 검색 중이면 일치하는 전체
	- 6-1) 고르는 즉시 채택하고 홈으로. 확인 버튼도, 완료 화면도 없다
	- 6-2) 제한된 최대 높이 안에서만 스크롤한다(스크롤바 숨김). 같은 UI가 바텀시트 안에서도 쓰여서 제한이 없으면 시트가 화면을 넘긴다
7. 빈 결과 — "검색 결과가 없어요"

#### 지역 데이터

| 항목 | 값 |
|---|---|
| 총 개수 | 451개 — 서울 행정동 424 + 경기 주요 동 27 |
| 출처 | 통계청 기준 서울시 행정동 중심점(2017) 실좌표 |
| 정렬 | 중심점 간 거리 근접순(하버사인) |

이름 충돌 처리 2건, 되돌리지 말 것

- 삼성동 — 행정동은 삼성1동·삼성2동이지만 기준 지역과 시드 제보가 전부 "삼성동"(선릉 일대)이라 하나로 합쳤다. 좌표는 선릉 기준
- 관악구 삼성동 / 강남구·은평구 신사동 — 이름이 겹쳐 구를 앞에 붙였다

#### 측위 경로

- 브라우저 위치 권한 → 좌표 → 역지오코딩 BFF(`app/api/geocode`) → 동 이름. 8초 안에 답이 없으면 끊는다. 권한 프롬프트를 방치하면 브라우저 자체 타임아웃이 안 걸리는 경우가 있어 별도 안전판을 둔다
- BFF는 3단이다. 카카오 REST 키가 있으면 카카오, 없으면 OpenStreetMap Nominatim, 둘 다 실패하면 삼성동으로 폴백한다. 키는 서버까지만 두고 화면 코드에 노출하지 않는다. 좌표는 숫자만 검증해 상류로 넘긴다
- "삼성1동" 같은 행정동 세분 이름은 숫자를 떼어 지역 목록 라벨과 맞춘다
- 변환된 동이 451개 목록에 없으면 실패로 보지 않고 삼성동으로 채택한다 — 시드가 없는 동을 고르면 화면이 통째로 비기 때문인데, 사용자에게는 엉뚱한 동네로 보인다 → `question.md`
