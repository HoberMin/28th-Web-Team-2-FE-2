# F00-1 온보딩 · 닉네임

경로 — `/prototype/onboarding` *(2026-08-05 코드 기준 재검토)*

> F00-1과 F00-2는 라우트가 하나다(`_components/onboarding-view.tsx`). 단계는 화면 안에서 전환되고, 단계별 딥링크나 뒤로가기 히스토리는 없다.
> 시작 단계는 저장값을 읽어 정한다 — 비회원(둘러보기)은 이 단계를 아예 건너뛰고 지역부터 받는다.

#### 정책

- 제보·댓글에 공개되는 이름이다. 본명은 쓰지 않는다
- 내 정보(F05-1)에서 언제든 바꾼다. 횟수 제한 없음 — 같은 2~10자 규칙을 쓴다
- 바꾸면 과거 내 제보에 남은 이름도 새 닉네임으로 보인다. 저장값을 고치지 않고 읽을 때 최신 닉네임으로 덮어써서 만든다
- 닉네임이 비어 있으면 제보·댓글에 "이웃"으로 표시된다

#### Description

1. 제목 — "사용할 닉네임을 알려주세요"
2. **닉네임 입력 필드** — placeholder "닉네임". 진입 시 자동 포커스(iOS Safari는 제스처 없이 키보드가 안 뜰 수 있다 — 실기기 한계로 수용)
	- 2-1) 글자수 카운터가 `현재/10` 형태로 붙는다
	- 2-2) 오류 문구는 입력을 시작한 뒤에만. 빈 화면이 빨갛게 뜨지 않게
3. **확인 버튼** — 형식이 맞을 때만 활성. 비활성이어도 자리는 유지한다(버튼이 새로 나타나면 입력 중 화면이 움직인다)
	- 3-1) 누르면 닉네임을 저장하고 곧바로 지역 단계로 넘어간다. 중복 확인 왕복이 없다
	- 3-2) 키보드 엔터도 같게 동작한다(폼 submit)
4. 여백 탭 — 입력·버튼 밖을 누르면 키보드를 내린다

#### 유효성 (코드에 있는 것만)

- 2자 이상 10자 이하. 앞뒤 공백을 지운 값으로 판정하므로 공백만 친 값은 빈 값과 같다
- 오류 문구는 한 가지뿐이다 — "2자 이상 입력해 주세요"
- 공백·특수문자 검사는 없다. 가운데 띄어쓰기나 특수문자가 섞여도 통과한다 *(미구현)*
- 중복·금칙어 검사는 없다. 계정 서버가 없어 확인 시점에 물어볼 곳이 없다 *(미구현)*
- 10자 상한이 입력 자체를 막지는 않는다 — 컴포넌트가 자른 값을 화면이 쓰지 않아 11자 이상도 들어오고, 그때 카운터는 상한을 넘고 문구는 "2자 이상 입력해 주세요"로 상황과 어긋난다 → `question.md`

실서비스에서 다시 살릴 문구 후보 *(미구현)*

| 상황 | 문구 |
|---|---|
| 공백·특수문자 포함 | 띄어쓰기 없이 한글, 영문, 숫자만 쓸 수 있어요 |
| 이미 쓰는 닉네임 | 이미 쓰고 있는 닉네임이에요. 다른 이름을 지어 주세요 |
| 금칙어 | 쓸 수 없는 닉네임이에요 |
| 통신 실패 | 잠시 후 다시 시도해 주세요 |

#### 상태 3종

| 상태 | 처리 |
|---|---|
| 로딩 | 해당 없음 — 서버 검사가 없어 확인이 즉시 끝난다 |
| 에러 | 길이 미달·초과. 입력 필드 인라인 문구 |
| 빈 | 초기 상태. 오류로 보지 않고 확인 버튼만 비활성 |

- 이탈 — 확인 → F00-2
- 뒤로가기 — 없음. 이 단계엔 헤더가 없다
