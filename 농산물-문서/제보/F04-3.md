# F04-3 제보 완료

경로 — `/prototype/report/success?item={품목id}&place={가게명}`

#### 정책

- 같은 가게의 다음 품목을 이어서 입력하는 경로가 이 화면의 존재 이유다. 가게 축 화면이 성립하려면 한 가게에 여러 품목 제보가 있어야 하는데, 품목마다 제보 흐름을 처음부터 타게 하면 가게마다 1~2건씩 흩뿌려진다
- 후기를 폼이 아니라 완료 화면에서 받는다. 폼은 이미 필드가 여럿이고 입력이 늘수록 제보가 준다. 완료 화면은 제보를 끝낸 뒤라 이탈 비용이 거의 없다
- 가격 만족도는 받지 않는다. 시세 대비 비율이 이미 정량으로 계산돼 중복이고, 우리가 못 가진 정보는 품질뿐이다
- 별점 5점이 아니라 3단계다. 서비스 성격이 가격 비교에서 가게 리뷰로 넘어가는 걸 막고, 5점 척도는 모바일에서 정확히 누르기 어렵다
- 후기는 여기서 저장만 하고 보여주지 않는다. 표시는 F09의 몫

#### Description

1. 일러스트 + "제보 성공!"
2. 가게명을 아는 경우 — "{가게명}에서 본 다른 가격도 같이 남겨주시면 이웃에게 큰 도움이 돼요"
3. **가게 신선도 후기** *(선택)* — "{가게명}, 전반적으로 어땠나요?"
	- 3-1) 좋아요 / 보통 / 별로
	- 3-2) 하나를 고르면 "한마디 남겨주세요 (선택)" 입력 칸이 나타난다
4. **「이 가게 가격 더 입력하기」** — 주 CTA. 가게명은 유지하고 품목만 비운 채 F04-2로
5. **「시세 보러 가기」** — 방금 제보한 품목의 F03으로
6. 두 버튼 어느 쪽으로 나가도 고른 후기를 저장한다. 연속 입력이 주 동선이라 그쪽에서 빠지면 후기가 조용히 버려진다

가게 없이 제보했으면 2·3·4를 그리지 않고 5만 남는다.

#### 상태 3종

| 상태 | 처리 |
|---|---|
| 로딩 | 없음 |
| 에러 | 없음 |
| 빈 | 가게 없이 한 제보 — 후기·연속 입력 영역을 통째로 뺀다 |

#### 화면 전환

- 진입 — F04-2 확인
- 이탈 — 연속 입력 → F04-2 / 시세 보기 → F03
