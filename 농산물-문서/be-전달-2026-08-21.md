## 1. 🔴 `/api/v1/regions/search` — 흔한 검색어가 전부 502

온보딩에서 **동네를 고를 수 없습니다.**

```
GET /api/v1/regions/search?keyword=서초
→ 502 {"code":"EXTERNAL_API_ERROR","message":"외부 API 호출 중 오류가 발생했습니다."}
```

### 재현

| keyword | 결과 |
|---|---|
| `신촌`(1건) · `판교`(2건) | 200 ✅ 좌표까지 정상 |
| `삼성` · `홍대` · `123` (0건) | 200 ✅ 빈 배열 |
| **`서초` `역삼` `대치` `삼성동`** | **502** ❌ |
| **`강남` `강남구` `종로` `부산` `제주`** | **502** ❌ |
| `동` · `가` · `abc` | 400 `INVALID_PARAMETER_ERROR` (정상 동작) |

**후보가 여러 건 잡히는 검색어만 실패**합니다. 0건이거나 1~2건이면 통과합니다.

### 원인

`external/kakao-client/.../feign/KakaoResponseDecoder.java`

```java
private void validateDocuments(final JsonNode documents, final Type type) {
    documents.forEach(document -> validateDocument(document, type));   // 배열 전체를 엄격 검증
}

private void validateAddress(final JsonNode address) {
    final JsonNode detail = address.get("address");
    if (detail == null || !detail.isObject()) {
        throw externalApiException();                    // :135  502
    }
    requireNonBlankText(detail, "region_3depth_name");   // :141  502
}
```

카카오 `/v2/local/search/address.json`은 문서마다 `address`(지번)와 `road_address`(도로명)를 주는데
**둘 중 하나가 `null`일 수 있습니다.** 도로명으로만 매칭된 결과는 `address: null`이고, 시·구 단위
결과는 `region_3depth_name`이 빈 문자열입니다.

**둘 다 카카오의 정상 응답인데 외부 API 장애로 오인**합니다. 게다가 배열 전체를 검사해서
**`SEARCH_SIZE = 30`건 중 한 건만 어긋나도 응답 전체가 502**가 됩니다. 검색어가 흔할수록 이런
문서가 섞일 확률이 올라가는 것이 위 재현표의 패턴입니다.

> **가설 표시**: "서초·역삼은 도로명 전용 항목 때문", "종로·부산은 `region_3depth_name`이 빈 값
> 때문"이라는 **건별 귀속은 가설**입니다(API 키가 없어 카카오 원본 응답을 직접 보지 못했습니다).
> **디코더가 두 경우를 502로 만든다는 것과, 한 건이 전체를 죽인다는 것은 코드로 확정**입니다.

### 이미 있는 방어가 무력화돼 있습니다

`KakaoRegionSearchAdapter`에는 이상 항목을 건너뛰는 방어가 이미 있습니다.

```java
final String bCode = address.bCode();
if (bCode.isBlank()) {
    return;                    // 쓸 수 없는 항목은 건너뛴다 — 의도가 맞습니다
}
```

그런데 **디코더가 그 앞에서 죽어** 여기까지 도달하지 못합니다. 어댑터의 의도(걸러 쓴다)와
디코더의 동작(하나라도 이상하면 전부 버린다)이 어긋난 상태입니다.

`KakaoResponseDecoderTest`(143줄)에 **`address: null` 케이스가 없어** 테스트에 안 잡혔습니다.
`KakaoRegionSearchAdapterTest`는 `bCode` 빈 문자열을 커버하지만 **디코더를 통과한 뒤**의
이야기라 이 결함을 잡지 못합니다. (`#220 숫자가 포함된 지역명 검색 허용`이 오늘 같은 경로를
만졌는데도 안 걸린 이유입니다.)

### 제안하는 수정

**"카카오의 정상 형태 차이"만 건너뛰고, 진짜 이상은 그대로 502**로 둡니다.

| 상황 | 수정 후 |
|---|---|
| `address`가 없거나 `region_3depth_name`이 빈 문서 | 그 문서만 버림 |
| 좌표 범위 이상 · 필수 필드 누락 · 빈 객체(`{}`) | **기존대로 502** |
| 응답 구조 자체가 깨짐 | **기존대로 502** (`validateEnvelope`) |
| `coord2regioncode` · 장소 검색 | **손대지 않음** (결과 형태가 균일해 누락이 곧 이상 신호) |

## 3. 🟡 `regionId` 타입이 엔드포인트마다 다릅니다

| 엔드포인트 | `regionId` |
|---|---|
| `/regions/search` | `"1141011400"` **문자열** |
| `/regions/{id}/items/{id}/reports` | `"1168010600"` **문자열** |
| **`/regions/nearby`** | `1168010600` **숫자** |

법정동 코드는 **앞자리 0이 유실되면 안 되는 코드값**입니다(예: `0111010100`).
지금은 프론트에서 10자리로 `padStart`해 복원하는데, **자릿수 고정을 가정한 우회**라 불안합니다.
`/regions/nearby`도 문자열로 통일해 주실 수 있을까요?

## 4. 🟡 `/regions/nearby`만 좌표를 안 내려줍니다

```
/regions/search → {"regionId":"...", "regionName":"...", "latitude":37.56, "longitude":126.93}
/regions/nearby → {"regionId":1168010600, "regionName":"강남구 대치동"}          ← 좌표 없음
```

같은 "지역"인데 응답 모양이 다릅니다. 프론트는 좌표가 필요해서 `nearby`로 고른 지역은
**이름으로 `search`를 다시 호출해 좌표를 복구**하고 있었습니다.
**1번 502를 실제로 밟은 경로가 이것**입니다 — 이 비대칭이 1번의 폭발 반경을 키웠습니다.

`nearby`도 좌표를 함께 주시면 이 재검색이 통째로 사라집니다.
그때까지는 프론트에서 조회에 쓴 사용자 좌표를 얹어 임시 우회해 뒀습니다(BE가 좌표를 주면 그쪽이 우선).

## 5. 🟡 `/items/{itemId}/online-prices` — `channelName`에 어떤 값이 오나요

```
GET /api/v1/items/1/online-prices
→ 200 {"itemId":1,"onlinePrices":[]}
```

**장애는 아닙니다** — 수집 전이라 빈 배열이 오는 것으로 보입니다. 다만 이 하나 때문에
프론트가 화면을 못 붙이고 있습니다.

시세 상세의 쇼핑몰 비교는 **로고를 컬리·오아시스·GS SHOP·11번가 4종으로 고정**해 두고 있습니다.
응답이 비어 있어 `channelName`에 어떤 문자열이 오는지 확인할 수 없어 로고 매핑을 짤 수 없습니다.
추측으로 짜면 4종 밖 채널이 왔을 때 조용히 깨집니다.

**부탁**: `channelName`·`channelKind`의 실제 값 목록을 알려주세요.
4종 밖이 있으면 저희가 디자이너에게 로고를 요청하겠습니다.

## 참고 1 — 스웨거 36개 오퍼레이션 전수 대조

`/api/samples` 2건은 샘플이라 제외한 **34건 기준**입니다.

### 라이브 호출 결과

공개 GET 13건 중 **`/regions/search` 502**(§1)와 **`/news` 503**(§2) 외에는 전부 200입니다.
아래 셋은 200이지만 데이터가 비어 있습니다 — 적재 전으로 보고 프론트는 더미 폴백을 유지했습니다.

| URI | 응답 |
|---|---|
| `/stores/recommendation` | `totalCount: 0` |
| `/items/{id}/online-prices` | `onlinePrices: []` |
| `/items/{id}/public-prices` | `points: []` |

### 동종 결함 점검

§1과 같은 **"한 건 어긋나면 전체 502"** 구조가 `validatePlace`(장소 검색)와
`validateRegion`(좌표→행정구역)에도 있습니다. 다만 **지금은 문제가 안 됩니다** — 좌표→행정구역은
결과가 1~2건이고 형태가 균일하며, 장소 검색의 `phone`·`road_address_name`은 `requireText`라
빈 문자열을 통과시킵니다(`requireNonBlankText`가 아닙니다).

**지금 고칠 결함은 아니라고 봅니다.** 다만 카카오가 형태를 바꾸면 같은 방식으로 터질 자리라
적어 둡니다.

## 참고 2 — 프론트가 처리한 것 (요청 아님)

### 신설 API 연결 (2026-08-21)

BE가 최근 추가해 주신 것들을 붙였습니다. 확인만 부탁드립니다.

| 시세 상세 | GET | `/api/v1/items/{id}/public-prices` | ✅ 화면 연결 (적재 전이라 비면 더미) |
| 시세 상세 | GET | `/api/v1/regions/{id}/items/{id}/reports` | ✅ 화면 연결 (비면 더미) |

| 마이페이지 | GET | `/api/v1/users/me/reports/weekly` | ✅ 화면 연결 (이번 주 제보) |
