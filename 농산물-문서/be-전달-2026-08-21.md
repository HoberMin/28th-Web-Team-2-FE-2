## 1. 🔴 `/api/v1/regions/search` — 흔한 검색어가 전부 502

```
GET /api/v1/regions/search?keyword=서초
→ 502 {"code":"EXTERNAL_API_ERROR","message":"외부 API 호출 중 오류가 발생했습니다."}
```

| keyword | 결과 |
|---|---|
| `신촌`(1건) · `판교`(2건) · `삼성`·`홍대`(0건) | 200 ✅ |
| **`서초` `역삼` `대치` `삼성동` `강남` `종로` `부산` `제주`** | **502** ❌ |

**후보가 여러 건 잡히는 검색어만 실패**합니다.

### 원인

`external/kakao-client/.../feign/KakaoResponseDecoder.java`

```java
private void validateDocuments(final JsonNode documents, final Type type) {
    documents.forEach(document -> validateDocument(document, type));   // 배열 전체를 엄격 검증
}

private void validateAddress(final JsonNode address) {
    final JsonNode detail = address.get("address");
    if (detail == null || !detail.isObject()) {
        throw externalApiException();                    // :135  502
    }
    requireNonBlankText(detail, "region_3depth_name");   // :141  502
}
```

카카오 `/v2/local/search/address.json`은 문서마다 `address`(지번)와 `road_address`(도로명)를 주는데
**둘 중 하나가 `null`일 수 있습니다.** 도로명으로만 매칭된 결과는 `address: null`, 시·구 단위 결과는
`region_3depth_name`이 빈 문자열입니다. **둘 다 카카오의 정상 응답인데 장애로 오인**하고,
배열 전체를 검사해서 **30건 중 한 건만 어긋나도 응답 전체가 502**가 됩니다.

참고로 `KakaoRegionSearchAdapter`에는 이상 항목을 건너뛰는 방어가 이미 있는데
(`if (bCode.isBlank()) return;`), **디코더가 그 앞에서 죽어** 도달하지 못합니다.

`KakaoResponseDecoderTest`에 `address: null` 케이스가 없어 테스트에 안 잡혔습니다.

### 제안

**"카카오의 정상 형태 차이"만 건너뛰고, 진짜 이상은 그대로 502**로 둡니다.

- `address`가 없거나 `region_3depth_name`이 빈 문서 → **그 문서만 버림**
- 좌표 범위 이상 · 필수 필드 누락 · 빈 객체(`{}`) · 응답 구조 파손 → **기존대로 502**
- **주소 검색에만 적용** (`coord2regioncode`·장소 검색은 결과 형태가 균일해 건드리지 않았습니다)

**검증**: `./gradlew :external:kakao-client:test :api:test` → **692건 통과 · 실패 0**.
회귀 테스트 3건 추가했고, 기존 `KakaoAddressSearchContractTest`의 502 계약은 그대로 통과합니다.

> **확인 부탁**: 이 수정은 쓸 수 있는 문서가 하나도 없으면 **빈 배열 200**을 돌려줍니다(예전엔 502).
> 프론트는 "검색 결과 없음"으로 표시하면 되니 낫다고 봤는데, 다르게 보신다면 알려주세요.

## 3. 🟡 `regionId` 타입 불일치

| 엔드포인트 | `regionId` |
|---|---|
| `/regions/search` | `"1141011400"` 문자열 |
| `/regions/{id}/items/{id}/reports` | `"1168010600"` 문자열 |
| **`/regions/nearby`** | `1168010600` **숫자** |

법정동 코드는 **앞자리 0이 유실되면 안 되는 코드값**입니다(예: `0111010100`).
지금은 프론트에서 10자리로 `padStart`해 복원하는데 자릿수 고정을 가정한 우회라 불안합니다.
`/regions/nearby`도 문자열로 통일해 주실 수 있을까요?

## 4. 🟡 `/regions/nearby`만 좌표를 안 내려줍니다

```
/regions/search → {"regionId":"...", "regionName":"...", "latitude":37.56, "longitude":126.93}
/regions/nearby → {"regionId":1168010600, "regionName":"강남구 대치동"}          ← 좌표 없음
```

프론트는 좌표가 필요해서 `nearby`로 고른 지역은 **이름으로 `search`를 다시 호출**하고 있었습니다.
**1번 502를 실제로 밟은 경로가 이것**입니다 — 이 비대칭이 1번의 폭발 반경을 키웠습니다.

`nearby`도 좌표를 함께 주시면 이 재검색이 통째로 사라집니다.
그때까지는 프론트에서 조회에 쓴 사용자 좌표를 얹어 임시 우회해 뒀습니다(BE가 좌표를 주면 그쪽이 우선).
