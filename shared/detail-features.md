- 기능 순서는 사용자 여정 순 — 기준 가격 → 동네 실제가 → 구매 판단 → 가게 선택 → 기록·재방문 → 탐색·진입

#### 기능 목록

- 기준 가격 5개 — 공공 시세 조회, 시세 그래프, 월별 최저가 시기, 이번 달 최저가 품목, 온라인가 비교
- 동네 실제가 6개 — 이웃 제보가, 촬영 제보, 가게 위치 특정, 제보 신뢰 표시, 구매 장소 공개, 근처 동네 가격
- 구매 판단 4개 — 즉석 판단, 시장 단위 환산, 가게 상세, 싼 가게 순위
- 가게 선택 1개 — 가게 목록
- 기록·재방문 11개 — 절약 요약(누적·주간 통합), 재구매 주기, 알림, 뱃지, 단골 가게, 오늘 최저가 품목, 제보왕 순위, 가게 댓글, 가게 신선도 후기, 카드뉴스, 내 제보 관리
- 탐색·진입 7개 — 야채 검색, 종류별 필터, 찜하기, 홈 시세 표시, 온보딩, 첫 제보 안내, 계정·설정

#### 설계 기준

- 판단은 3초 이내 완료. 사용자가 앱을 켜는 순간은 가게 가격표 앞이고, 그 자리에서 안 끝나는 기능은 정확해도 안 쓰임
- 답은 품목이 아니라 가게 단위. 사용자의 질문은 감자 가격이 아니라 오늘 갈 가게. 품목별 최저가만 주면 가게가 흩어져 발걸음 증가
- 절약액과 발걸음 동시 노출. 돈만 아끼게 하면 노력 절약을 잃음. 선택은 사용자 몫
- 제보는 장보기의 부산물. 따로 요청하면 안 함. 판단하려고 이미 넣은 가격을 그대로 제보로 전환
- 근거 없는 숫자 금지. 기준 없으면 판정 보류, 낡은 제보는 낡음 표시
- 계획이 아니라 선택을 돕는다. 살 목록을 담아두는 기능은 찜하기와 구별되지 않아 배제. 사용자의 질문은 무엇을 담았나가 아니라 오늘 어느 가게 갈까

#### 공공 시세 조회

- 정의 — 농산물유통정보 46종의 오늘 시세·평균가·기간별 추이 제공
- 해결하는 문제 — 판단 기준선 부재. 감에 의존한 구매

- 참조 — 품목코드·품종코드·등급코드·단위는 전부 `kamis-vegetable-data-spec.md` v3가 진실 소스. 이 문서에 코드값을 복제하지 않는다. 스코프는 채소류와 특용작물이며 축산물·수산물은 제외, 과일 중 수박·참외·멜론·딸기는 규격상 채소류로 분류돼 포함

- 동작
  - 매 요청에 파라미터 4개를 전부 명시. 품목분류·품목·품종·등급
  - 등급은 상품 고정. 스코프 전 품목에서 연중 존재함을 실측 확인했고, 중품은 표본이 얇아 며칠씩 값이 안 바뀌는 등 품질이 낮았음
  - 단위는 품목별 분기. kg·g 품목은 kg 환산 요청, 개·포기 품목은 환산 없이 원 단위 유지. 오이는 kg 환산이 성립하지 않아 개수 단위
  - 배추·무는 품종이 아니라 계절로 갈림. 봄·여름고랭지·가을·월동을 전부 조회해 응답 있는 것만 평균. 달력으로 시즌 고정 금지
  - 오늘 시세·평균가·기간별 1주·1개월·1년 값 생성
  - 수박·참외·딸기·갓은 비수기 데이터 없음이 정상

- 화면 요소
  - 비수기 품목은 가격 대신 계절 문구로 대체
  - 조회 실패 시에도 화면이 비지 않게 대체값 표시
  - 유사 품목은 규격 단계에서 이미 분리됨. 애호박과 쥬키니, 대파와 쪽파, 적상추와 청상추, 방울토마토와 대추방울토마토, 고춧가루 국산과 중국산. 화면에서도 합치지 않는다

- 결정 필요
  - 방울토마토·대추방울토마토 화면 표기. 규격상 개 단위가 맞지만 개당 수백 원이라 화면에서 어색함. 팩 환산 표기 여부는 표시 층의 결정
  - 규격 문서가 v3에서 정리한 배제 품목이 늘거나 줄 때의 갱신 주체

  - 키보드로도 지점 이동 가능. 좌우 화살표로 한 칸, Home·End로 양 끝. 터치 전용이면 키보드 사용자는 최신 지점 하나만 확인 가능

#### 월별 최저가 시기

- 정의 — 1년 월평균 중 최저 달을 찾아 시세 화면에 표시
- 해결하는 문제 — 구매 시점 판단 근거 부재

- 동작
  - 1년 월평균 중 최저 달 계산
  - 이번 달 대비 하락률 함께 표시

- 화면 요소
  - 최저 달이 이번 달보다 안 싸면 배지 숨김. 의미 없는 정보 미노출

- 결정 필요
  - 달력상 제철 정보 병기 여부
  - 이번 달 최저가 품목과 계산 근거가 같아 통합 여부 검토

#### 이번 달 최저가 품목

- 정의 — 1년 월평균에서 이번 달이 저점권 3위 이내인 품목만 홈 상단에 노출
- 해결하는 문제 — 계절별 저가 품목 파악 불가. 달력상 제철이 아니라 실시세 계산값

- 동작
  - 품목별로 이번 달의 1년 내 저가 순위 계산
  - 6위 이내 + 연 최고가 대비 2% 이상 저가인 품목 채택. 부족하면 할인폭 상위로 채움
  - 할인폭 큰 순으로 최대 6개. 가로 스크롤

- 화면 요소
  - 연 최고가 대비 하락률 + 근거 라벨
  - 조건 완화로 섹션이 사라지는 달은 사실상 없음

- 결정 필요
  - 채택 기준 6위·2%의 적정성. 원래 3위·5%였으나 통과 0개인 달에 섹션이 통째로 사라져 화면 확인이 불가했음. 보이게 하려고 푼 임시값이라 근거 없음
  - 월별 최저가 시기와 통합 여부

#### 온라인가 비교

- 정의 — 컬리·오아시스·GS SHOP·11번가 가격을 판매 방식과 함께 표시. 오프라인 판단의 보조 기준
- 해결하는 문제 — 공공 시세만으로는 채널별 가격차 확인 불가

- 동작
  - 채널별 가격을 품목 기준 단위로 환산
  - 환산 불가 상품은 미포함. 억지 환산이 정보 부재보다 위험
  - 가로 막대 비교로 표시하고 같은 축에 동네 제보가 기준선을 얹음. 제보 부재 시 오늘 시세
  - 채널별 판매 방식은 막대 아래 라벨 한 줄. 방식은 새벽배송·당일배송·오픈마켓·즉시배송, 단서는 배송비 별도·회원가

- 화면 요소
  - 세로 리스트 금지. 온라인끼리만 비교돼 이 화면이 답해야 할 질문인 동네와 온라인 중 어디가 싼가에 답하지 못함
  - 판매 방식 필수 표기. 즉시배송은 소량이라 구조적으로 고가, 오픈마켓은 배송비 별도. 방식 없이 금액만 줄 세우면 즉시배송이 제일 비싸다는 결론만 반복돼 정보량 0
  - 46종 전 품목에 값 존재. 섹션이 있다 없다 하면 화면 규격을 하나로 잡을 수 없어 전 품목을 채움. 컬리만 실측이고 나머지 3채널과 미수집 품목은 더미. 화면에는 라벨을 붙이지 않고 이 문서로 관리
  - 채널별 항목 선택 시 해당 몰 검색으로 이동. 상품 단위 딥링크는 상품 코드가 바뀌어 죽은 링크가 되므로 품목 검색으로 연결
  - 오프라인 동네 가격이 기준이고 온라인은 참고용임을 하단에 명시

- 결정 필요
  - 가격 갱신 주기
  - 채널별 연결 방법. 각 몰의 검색 URL·상품 코드 수명·판매자별 편차가 달라 일괄 처리 불가

#### 이웃 제보가

- 정의 — 이웃이 올린 실제 목격 가격을 행정동 단위로 집계해 표시
- 해결하는 문제 — 공공 시세가 광역 단위까지만 나와 동네 가격 확인 불가. 서비스의 유일한 차별점

- 동작
  - 제보 방식 선택. 촬영 / 직접 입력 — 제보 전용(가격만 확인은 제거, 판단 진입은 시세 화면 상단 CTA로 복원 — 2026-07-31)
  - 촬영이면 촬영 화면을 거쳐 제보 폼. 가게 위치는 폼 안 drawer에서 선택
  - 품목은 초성 검색 시트에서 선택
  - 양·가격 입력. 양의 단위는 품목별. 촬영·즉석 판단 경유 시 프리필
  - 구매 여부 선택. 구매 또는 목격
  - 제출 후 완료 화면. 동네 제보가 목록에 반영
  - 완료 화면에서 같은 가게의 다음 품목을 이어서 입력 가능. 가게명은 유지하고 품목만 교체

- 화면 요소
  - 연속 입력 경로 필수. 가게 축 화면이 성립하려면 한 가게에 여러 품목 제보가 있어야 함. 품목마다 제보 흐름을 처음부터 다시 타게 하면 가게마다 1~2건씩 흩뿌려져 이 가게가 전반적으로 싼가에 답할 수 없음
  - 가게 위치 선택은 별도 화면이 아니라 폼 안 drawer. 어디서 봤나를 뭘 얼마에보다 먼저 묻는 순서가 사용자 인식과 반대였고, 폼에서 가게를 바꾸려면 뒤로 갔다 와야 했음
  - 품목은 자유 텍스트 금지. 품목명 완전 일치라야 통과해 햇감자 같은 입력이 무효였고 확인 버튼이 왜 비활성인지 알 수 없었음
  - 이미 정해진 값인 위치·품목은 상단 요약 칩으로 접고 실제 입력할 양·가격만 필드로 노출. 넷을 같은 무게로 두면 이 폼의 주인공인 가격이 안 읽힘
  - 위치는 시트 선택값으로 고정. 자유 편집이면 오타로 같은 가게가 둘로 갈라져 가게 집계가 깨짐
  - 목록은 카드형 2줄. 윗줄 가게명·가격, 아랫줄 제보 시점·확인 인원·시세 대비 차이. 3열 표는 첫 열에만 4단이 쌓여 비교 대상인 가게명이 날짜에 딸린 부속으로 읽혔음
  - 시세 대비 차이는 가격과 같은 급. 사용자가 실제로 훑는 정보
  - 정렬은 싼 순·최신순. 판단에 필요한 건 대개 어디가 제일 싼가
  - 위치 확인 중 안내는 입력값을 덮지 않고 안내 문구로만. 값을 치환하면 사용자가 먼저 적은 가게명이 사라짐
  - 시세 그래프보다 위에 배치. 그래프는 참고 자료이고 동네 제보가가 구매 판단의 직접 근거
  - 가게명 선택 시 해당 가게의 전 품목 가격으로 이동
  - 제보 없는 동네는 빈 화면 대신 근처 동네 가격 노출

- 결정 필요
  - 허위 제보 신고·제재 기준. 현재는 이상치 표시까지만

#### 촬영 제보

- 정의 — 사진 촬영으로 품목·양·가격을 프리필해 제보 시간 단축
- 해결하는 문제 — 허위·장난 제보 필터 부재. 사진으로 신뢰도 보강

- 동작
  - 카메라 실행
  - 셔터로 화면 고정
  - 인식 결과 확인
  - 구매 여부 선택 후 제출

- 화면 요소
  - 라이브 / 인식 중 / 오류 3가지 상태 필요. 오류는 권한 거부 상황
  - 카메라 권한 거부 시 직접 입력으로 유도
  - 촬영 진입 경로는 제보 방식 선택 화면 한 곳뿐

- 결정 필요
  - 실제 이미지 인식 도입 시점. 현재는 항상 감자로 인식되는 예시 동작

#### 가게 위치 특정

- 정의 — 현재 위치로 근처 청과물·마트를 찾아 제보 위치를 동보다 좁게 특정. 별도 화면이 아니라 제보 폼 안의 drawer
- 해결하는 문제 — 동 단위로 받아도 가게 식별 불가

- 동작
  - 현재 GPS 좌표로 카카오 로컬 키워드 검색. 청과·채소가게·과일가게·마트, 반경 2km, 거리순
  - 키 미설정·업스트림 실패·0건이면 더미로 폴백. 인증키는 서버까지만
  - 목록에서 선택. 미등록 시 직접 입력

- 화면 요소
  - 직접 입력 전환 시 목록을 숨기지 않고 아래에 입력 칸을 펼침. 직접 입력하려다 목록에서 발견하는 경우가 흔해 숨기면 그 기회가 사라짐. 버튼 라벨도 현재 상태 반영

- 결정 필요
  - 반경 2km의 적정성. 현재는 근거 없는 초기값
  - 지도 서비스 연결 시점

#### 제보 신뢰 표시

- 정의 — 제보마다 신뢰 신호 3가지를 부착해 신뢰도 판단 지원
- 해결하는 문제 — 이웃 제보가가 유일한 차별점인데 검증 장치 부재. 틀린 제보 하나가 서비스 전체 신뢰를 훼손

- 동작
  - 최신도 — 오늘 / 어제 / N일 전. 1주일 초과 시 흐리게 처리하고 오래된 가격임을 명시. 야채 가격은 주 단위로 변동해 낡은 제보를 같은 무게로 노출하면 오판 유발
  - 교차 검증 — 같은 가게·같은 품목 제보 2건 이상이면 확인 인원 표시. 1건은 근거가 얇고 2건부터 상호 증인
  - 이상치 — 시세의 3배 초과 또는 3분의 1 미만은 오타·장난 확률 높음. 삭제하지 않고 목록 하단으로 이동, 확인 필요 표시, 평균 계산에서만 제외

- 화면 요소
  - 시세 화면 제보 목록과 가게 상세에 동일 규칙 적용

- 결정 필요
  - 이상치 기준 3배·3분의 1의 적정성
  - 오래됨 기준 7일의 품목별 차등 여부

#### 구매 장소 공개

- 정의 — 제보 목록에 방문 가게명 노출. 선택 시 가게 화면으로 이동
- 해결하는 문제 — 가격만으로는 방문할 가게를 알 수 없음. 가게 단위 조회의 입구 역할

- 동작
  - 제보 시 선택한 가게 저장
  - 목록에 가게명 표시
  - 선택 시 가게 상세로 이동

- 화면 요소
  - 가게 미선택 제보는 가게명 줄 생략

- 결정 필요
  - 가게 사장 반발 시 비공개 옵션 도입 여부

#### 근처 동네 가격

- 정의 — 우리 동네 제보 부재 시 가까운 동네 3곳의 가격을 출처와 함께 표시
- 해결하는 문제 — 제보 없는 동네는 화면 대부분이 빈 상태. 이웃 제보 기반 서비스의 첫 사용자가 반드시 만나는 상태이고, 빈 화면만 보면 데이터 없는 앱으로 판단하고 이탈

- 동작
  - 우리 동네 제보 0건 여부 확인
  - 거리순으로 훑어 제보 있는 동네 3곳 선정
  - 동네명·최신 가격·시세와의 차이·최신도 노출

- 화면 요소
  - 우리 동네 값이 아님을 문구로 명시. 정확도는 낮아도 출처를 밝히면 오해 없고, 아무것도 없는 상태보다 유용

- 결정 필요
  - 거리 상한
  - 근처 동네 값의 판정 기준 활용 여부. 현재는 표시만

#### 즉석 판단

- 정의 — 품목·단위·가격 입력만으로 우리 동네 기준 사도 좋음 / 적당함 / 비쌈 세 가지 중 하나를 한 화면에 표시. F10
- 해결하는 문제 — 가게 가격표 앞에서 앱을 켜는데 홈·검색·품목·시세 화면을 여러 번 스크롤해야 판단 완료. 판단까지의 거리가 과다

- 동작
  - 홈 최상단 또는 시세 화면에서 진입
  - 품목 선택. 찜한 야채와 자주 찾는 야채 우선 노출, 검색 병행
  - 파는 단위 선택. 1kg·1단·1망·1박스 등. 환산은 앱 처리
  - 가격 입력. 입력 중 실시간 판정
  - 판정 후 제보 연결. 입력값 그대로 제보로 이월

- 판정 기준
  - **오늘 공공 시세(KAMIS)** 단일 기준. 가게 상세·가게(F03-3·F03-2)과 동일 기준선을 써서 같은 가격이 화면마다 다르게 판정되는 모순을 없앰(2026-07-31 변경 — 이전엔 우리 동네 최저 제보가 우선이었음)
  - 우리 동네 제보가는 화면에 계속 노출하되 판정에는 미반영. 참고 정보로만 취급
  - 기준 대비 8% 이상 저가는 초록, 8% 이상 고가는 빨강, 사이는 노랑

- 화면 요소
  - 판정 카드는 결론 → 근거 → 다음 행동 순서. 비교 대상은 항상 공공 시세, 동네 제보 건수는 참고 정보로 구분 표시
  - 색 단독 전달 금지. 문구가 결론을 그대로 진술
  - 표식은 아이콘. 색과 기호의 뜻을 일치시킴. 이모지는 기기·폰트마다 다르게 렌더링돼 디자인 통제 불가
  - 시세 데이터 없는 품목은 판정 보류 후 제보 유도
  - 하단 버튼은 항상 자리 유지, 비활성 상태로 노출. 판정 시점에 버튼이 새로 나타나면 입력 중 화면 이동 발생

- 결정 필요
  - 8% 기준의 적정성
  - 품목별 차등 여부

#### 시장 단위 환산

- 정의 — 시장 판매 단위 1단·1망·1박스·묶음을 비교 가능한 기준 단위로 환산
- 해결하는 문제 — 46종의 기준 단위가 kg·g·개·포기로 갈리고 시장은 kg 판매가 드묾. 환산 없이는 비교 자체가 불가

- 참조 — 품목별 기준 단위는 `kamis-vegetable-data-spec.md`의 단위 열. 이 값이 환산의 도착점이라 임의로 바꾸면 시세와 제보가가 다른 축에서 비교됨

- 동작
  - 품목 단위에 맞는 후보 제시. kg 품목은 1kg·1단·1망·1박스, 개 품목은 1개·3개 묶음·1봉지
  - 사용자가 판매 단위 선택 후 그 단위의 가격 입력
  - 기준 단위로 환산하고 환산 근거를 문구로 노출

- 화면 요소
  - 즉석 판단과 제보 폼에 단위 선택 필요

- 결정 필요
  - 1단·1망 환산 계수. 현재 단 0.8kg·망 1.5kg 가정. 지역·품목마다 달라 실측 필요. 이 값이 틀리면 판정 전체가 틀림

#### 가게 상세

- 정의 — 한 가게의 전 품목 가격을 한 화면에 집계. F03-3 (`F03_가게상세`)
- 해결하는 문제 — 전 화면이 품목 단위라 방문할 가게에 답하는 화면 부재. 서비스가 풀려는 문제인 가게 비교에 정면으로 답하는 화면

- 동작
  - 싼 가게 순위, 제보 목록의 가게명, 홈 단골집 카드에서 진입
  - 제보를 가게별로 집계. 같은 품목은 최신 1건을 대표로 채택. 가격은 시간에 민감
  - 시세 대비 저가 품목 순 정렬. 방문 이유가 먼저 읽혀야 함
  - 우측 상단에서 단골 등록

- 화면 요소
  - 요약 한 줄 — 제보 품목 수, 시세보다 싼 품목 수, 최근 제보 시점
  - 위치를 가격 목록보다 먼저 배치. 갈 만한 거리인가가 정해져야 가격을 볼 이유가 생김. 지도, 주소, 내 위치에서의 거리와 도보 시간
  - 좌표는 제보에 실려 오지 않음. 동 중심에 가게명 해시 오프셋을 더해 결정적으로 생성. 실서비스에서는 장소 검색 좌표로 교체
  - 지도는 지도 앱키가 있을 때만 렌더. 없으면 주소와 거리만 남기고 화면은 깨지지 않음
  - 섹션 제목은 이 가게에 제보된 가격. 가게가 게시한 공식 가격표가 아니라 이웃이 보고 남긴 값이라, 이름이 출처를 숨기면 틀린 값의 책임이 가게로 감
  - 품목마다 최신도·확인 인원·이상치 표시
  - 제보 없는 가게도 위치는 노출. 그 화면에서 유일하게 확실한 정보
  - 뒤로가기는 진입 경로로 복귀. 여러 경로에서 들어오는 화면이라 목적지 고정 시 오작동

- 결정 필요
  - 가게 단위 비공개 옵션. 구매 장소 공개와 동일 사안

#### 싼 가게 순위

- 정의 — 우리 동네 가게를 시세 대비 평균이 낮은 순으로 정렬
- 해결하는 문제 — 품목별 최저가만 제시하면 가게가 흩어짐

- 동작
  - 시세 대비 평균 저가 순 정렬
  - 동일 시 제보 많은 순. 근거가 두꺼운 쪽 우선

- 화면 요소
  - 가게별 제보 부재 시 빈 상태 + 제보 시 가게 선택 유도

- 결정 필요
  - 실서비스 집계 주기. 실시간 또는 일 1회

#### 가게 목록

- 정의 — 동네 가게를 시세 대비 편차 평균이 낮은 순으로 나열. 상단은 내 단골 가게. F03-2 (`F03_가게`). 랭킹에 있던 싼 가게 탭이 여기로 흡수됐다(같은 집계·같은 줄 컴포넌트라 두 화면일 이유가 없었음)
- 해결하는 문제 — 전 화면이 품목 축이라 방문할 가게를 고르는 화면 부재. 사용자의 질문은 감자 가격이 아니라 오늘 갈 가게

- 동작
  - 현재 동의 제보를 가게별로 집계
  - 순위 기준은 시세 대비 편차 평균. 제보가 단순 평균이 아님. 가게마다 제보된 품목 구성이 달라 금액을 그대로 평균하면 비싼 품목이 많이 제보된 가게가 무조건 비싸 보이고, 가게가 아니라 품목 구성을 비교하게 됨
  - 동일 시 제보 많은 순. 근거가 두꺼운 쪽 우선
  - 줄에서 바로 단골 등록·해제. 화면 이동 없이 여기 자주 가는 데야를 남길 수 있어야 함
  - 단골로 등록한 가게는 상단으로 분리

- 화면 요소
  - 줄마다 시세 대비 평균, 거리와 도보 시간, 제보 품목 수, 최신도
  - 단골 0개여도 하단 동네 목록이 화면을 채움. 첫 사용자에게 빈 탭을 주지 않음
  - 절약액과 발걸음 동시 노출. 싼 것만 보여주면 발걸음이 늘어 절약이 상쇄됨

- 결정 필요
  - 홈 단골집 카드와의 중복 처리. 축이 같아져 홈 카드를 남길지 미정

#### 절약 요약

- 정의 — 구매분만 집계해 그날 시세와 비교, 절약·초과 금액 산출. 기간 토글(이번 주·전체)이 달린 카드 하나로 마이페이지 상단 고정
- 해결하는 문제 — 구매 후 적정성 판단 불가. 제보 유인도 여기서 발생. 누적만 있으면 첫 달 이후 숫자가 커져 변화 체감 불가한데, 장보기는 주 단위 리듬이라 주간이 체감 단위

- 동작
  - 구매 표시 제보 조회. 그날 시세와 비교해 절약·초과 산출
  - 이번 주는 최근 7일. 절약액 최대 품목을 최우수 구매로 지목

- 화면 요소
  - 누적과 주간을 카드 두 장으로 나누지 않음. 같은 지표를 기간만 바꿔 두 번 말하며 화면만 늘림
  - 마이페이지 허브에서 메뉴 뒤로 숨기지 않음. 핵심 가치가 눈으로 보는 변화라 감추면 마이페이지에 들어올 이유가 사라짐
  - 구매 0건이면 제보 시 절약액 확인 가능함을 안내
  - 절약은 초록, 초과는 주황
  - 칭찬 대상 구체화 필요. 품목명·금액·가게명 동시 노출

- 결정 필요
  - 초과 시 문구 톤. 비난으로 읽히지 않는 표현
  - 주 시작 기준. 월요일 고정 또는 최근 7일. 현재는 최근 7일

#### 재구매 주기

- 정의 — 구매 간격에서 재구매 시점을 추정해 마이페이지 구매 화면 상단에서 안내
- 해결하는 문제 — 시세 확인을 위해 매번 앱 실행 필요

- 동작
  - 품목별 구매 간격 평균을 주기로 사용
  - 이력 1건이면 근거 부재로 14일 기본값 사용. 가정임을 문구로 명시
  - 주기 초과 품목만 경과일 순으로 최대 4개

- 화면 요소
  - 홈이 아니라 마이페이지 구매 화면에 배치. 구매 이력 2건 이상이라야 의미 있는 추정인데 그때쯤이면 마이페이지를 아는 사용자고, 데이터 출처도 구매 내역과 같음
  - 메뉴 라벨은 구매 내역이 아니라 구매. 과거 기록과 다음 구매 안내를 같이 담기 때문
  - 마지막 구매 경과일과 평균 주기 병기
  - 해당 품목 부재 시 미노출

- 결정 필요
  - 알림과 역할 분담. 양쪽 다 재방문 시점을 만드는 장치라 하루 1회 다이제스트와 이 안내가 같은 날 겹쳐 뜨면 잔소리로 읽힘

#### 알림

- 정의 — 알림 전체 켜기·끄기 전역 토글 하나. 대상은 별도 등록 없이 찜한 야채와 단골 가게. 화면만 구현, 실제 발송 없음
- 해결하는 문제 — 시세 확인을 위해 매번 앱 실행 필요. 이전엔 가게마다 개별 토글이었는데, 알림을 받아도 그래서 어디로 가지가 남아 행동으로 이어지지 않았고 품목 알림·가게 알림 두 체계를 따로 배워야 했음

- 동작
  - 진입은 「내 정보」 화면(계정·설정) 하나. 단골 가게 화면에는 목록·해제만 남고 알림 토글은 없음
  - 트리거는 매일의 등락 전부가 아니라 의미 있는 변화만. 찜한 야채는 최근 평균 대비 일정 % 이상 하락했을 때만, 단골 가게는 그 가게에 시세보다 싼 제보가 새로 올라왔을 때만
  - 이상치 제보(시세 3배·⅓ 밖)는 집계에서 제외 — 가게 요약·「제보 신뢰 표시」와 같은 기준. 오타 제보 하나가 알림으로 울리면 안 됨
  - 건건이 보내지 않고 하루 한 번 묶어 다이제스트로 발송

- 화면 요소
  - 「내 정보」 알림 항목 아래 「오늘 이런 알림을 받아요」 미리보기. 찜·단골·제보·시세에서 실제로 계산해 한 줄로 조립. 예: "오늘 삼성동 — 감자 12% 내렸어요 · 행복청과에 새 제보 3건"
  - 대상(찜·단골) 자체가 없으면 "아직 알림 받을 야채나 가게가 없어요. 찜하거나 단골로 등록해 보세요"
  - 토글이 꺼져 있으면 미리보기를 흐리게 표시
  - 전역 토글 하나뿐이라 가게별·품목별 개별 끄기가 없음. 그래서 트리거 기준(의미 있는 변화만 + 하루 1회 묶음)이 볼륨을 관리하는 유일한 장치 — 이 기준이 헐거우면 전체를 끄는 것 말고는 피할 방법이 없음

- 결정 필요
  - 가격 하락 임계값 10%(최근 30일 평균 대비)의 적정성. 근거 없는 초기값
  - "새로 올라온" 제보로 볼 기준일수 1일의 적정성. 근거 없는 초기값
  - 발송 인프라 도입 시점

#### 뱃지

- 정의 — 제보·구매 건수 기준 통과 시 단계별 뱃지 부여
- 해결하는 문제 — 제보 유인 부재

- 동작
  - 제보·구매 건수 집계
  - 기준 통과 여부 판정. 제보 1·5·15건, 구매 3건

- 화면 요소
  - 미획득 뱃지도 흐리게 노출해 다음 목표 제시

- 결정 필요
  - 종류·기준의 실사용 데이터 기반 재조정 여부

#### 단골 가게

- 정의 — 자주 가는 가게를 등록해 가게 탭 상단과 홈에서 우선 확인
- 해결하는 문제 — 반복 구매가 타깃 특성인데 매번 가게 재탐색

- 동작
  - 등록·해제 지점 3곳 — 가게 상세 우측 상단, 가게 탭 목록의 줄, 마이페이지 단골 가게 화면
  - 목록에서 바로 토글되어야 함. 등록하려고 상세로 들어갔다 나오게 하면 남기지 않음
  - 가게 탭 상단과 홈 요약 카드에 반영. 품목 수, 최근 제보 시점, 시세 대비 평균
  - 별도 등록 없이 알림의 대상이 됨. 단골 = 구독. 그 가게에 시세보다 싼 제보가 새로 올라오면 알림 다이제스트에 포함(「알림」 참조). 알림 토글 자체는 여기가 아니라 「내 정보」에 있음

- 화면 요소
  - 단골 부재 시 홈 카드는 렌더 생략. 빈 카드로 홈 길이 증가 금지
  - 아이콘 단독 버튼이라 켜짐·꺼짐을 이름표로도 전달

- 결정 필요
  - 등록 개수 상한
  - 홈 요약 카드 존치 여부. 가게 탭과 축이 같아져 중복

#### 오늘 최저가 품목

- 정의 — 동네 제보에서 오늘 가장 싸게 목격된 품목 순위. **홈**에 배치
- 해결하는 문제 — 시세 화면만으로는 재방문 이유 부족

- 동작
  - 품목마다 가장 싼 제보 1건만 채택. 같은 품목이 목록을 채우면 순위가 아니라 나열이 됨
  - 이상치와 7일 초과 제보는 제외. 오늘 최저가라고 부를 수 없는 값
  - 시세 대비 할인폭이 큰 순으로 최대 5개

- 화면 요소
  - 기준 동네 명시
  - 홈의 제철 추천과 나란히 두되 합치지 않는다. 이쪽은 오늘 이웃이 실제로 본 가격, 저쪽은 1년 시세에서 뽑은 계절 저점이라 근거가 다름
  - 랭킹 탭이 아니라 홈에 있다. 랭킹은 제보왕 단독으로 재편했고, 이 목록은 성격상 홈의 추천 콘텐츠에 가깝다

- 결정 필요
  - 실서비스 집계 주기

#### 제보왕 순위

- 정의 — 동네 제보 상위 사용자 순위. 랭킹 화면(F06)의 유일한 콘텐츠
- 해결하는 문제 — 재방문 이유 부족. 크라우드소싱은 기여에 보상이 없으면 마름

- 동작
  - 현재 동 제보를 닉네임별로 집계. 내가 제보하면 내 순위가 오른다
  - 사람을 누르면 공개 제보 목록(F06-1)으로 이동

- 화면 요소
  - 기준 동네 명시
  - 1·2·3위를 시각적으로 구분. 순위 화면인데 1위와 4위 렌더가 같으면 순위가 부가정보로 읽힘
  - 비교값은 닉네임이 아니라 제보 건수. 건수를 더 크게
  - 공개하는 값은 닉네임·아바타·순위·건수까지. **본명은 쓰지 않는다**
  - 공개 제보 목록에는 품목·가격·가게·시점만. 구매 여부·절약액은 개인 정보라 뺀다

- 결정 필요
  - 실서비스 집계 주기
  - 집계 키. 지금은 닉네임 문자열이라 실서비스에선 닉네임 변경이 곧 순위 초기화·사칭 수단이 된다. 표시값과 집계 키를 분리할지

#### 카드뉴스

- 정의 — 요즘 저가·고가 품목을 홈에서 먼저 알려주는 콘텐츠
- 해결하는 문제 — 그래프는 능동 조작이 필요. 수동적으로도 정보 전달

- 동작
  - 가로 스와이프 캐러셀 + 점 인디케이터. 이전엔 첫 글 하나만 고정 노출이라 나머지에 도달할 길이 없었음

- 화면 요소
  - 자동 롤링 금지. 글이 몇 개뿐이라 자동 순환으로 얻을 게 없고, 읽는 중 넘어가면 타깃 연령대에 불만이 큼. 자동으로 하면 정지 버튼을 추가해야 함
  - 홈에서는 야채 목록 아래 배치. 개인화 카드가 여러 장 노출되는 날에는 주 콘텐츠 46종 목록이 첫 화면 밖으로 밀림

- 결정 필요
  - 콘텐츠 작성 주체. 사람 작성 또는 시세 계산 기반 자동 생성

#### 내 제보 관리

- 정의 — 마이페이지 내 제보 화면에서 자기 제보를 수정·삭제
- 해결하는 문제 — 오타 제보를 되돌릴 방법 부재. 시스템은 이상치로 흐리게 표시만 하고 본인은 못 고치는 CRUD 구멍

- 동작
  - 항목 우측 더보기 메뉴에서 수정·삭제
  - 수정은 제보 폼으로 되돌리지 않고 가격·양만 고치는 시트로 처리
  - 삭제는 확인 단계를 둠

- 화면 요소
  - 스와이프 삭제 금지. 있는 줄 모르면 영원히 못 찾고 타깃 연령대에 불리. 명시적 메뉴로 노출

- 결정 필요
  - 수정 이력 보존 여부. 현재는 덮어쓰기라 이웃이 이미 본 값이 조용히 바뀜

#### 가게 댓글

- 정의 — 가게 상세(F03-3, `F03_가게상세_댓글`)에서 그 가게에 대한 이웃 간 짧은 소통
- 해결하는 문제 — 제보가 일방향 데이터라 이웃 간 신뢰·소통 미형성

- 동작
  - 같은 가게 댓글만 노출
  - 닉네임과 내용 입력

- 화면 요소
  - 시세 화면(품목별)에 두지 않음. 46종 × 동네 수로 흩어져 밀도가 안 나고, 판단 화면에 대화가 붙으면 판단 정보가 밀림. 애초에 댓글이 다루는 화제가 품목이 아니라 어디가 싸더라, 즉 가게 단위
  - 댓글 부재 시 빈 상태 문구
  - 한글 입력 중 엔터로 미완성 글자 제출 방지

- 결정 필요
  - 구매자 한정 댓글 게이트 도입 여부

#### 가게 신선도 후기

- 정의 — 제보 완료 화면에서 그 가게의 신선도를 좋아요·보통·별로 3단계로 남김. 한마디 병기 가능. 전부 선택 사항
- 해결하는 문제 — 가격은 정량으로 비교되지만 품질은 알 수 없음. 싼데 상태가 별로인 가게를 구분할 방법이 없었음

- 동작
  - 제보 제출 후 완료 화면에서 선택. 건너뛰어도 완료
  - 표시 자리는 가게 상세. 가게 댓글과 같은 곳

- 화면 요소
  - 제보 폼이 아니라 완료 화면. 폼은 이미 필드가 여럿이고 핵심 가치가 노력 절약이라 입력이 늘수록 제보가 줆. 완료 화면은 제보를 끝낸 뒤라 이탈 비용이 거의 없음
  - 가격 만족도는 받지 않음. 시세 대비 비율이 이미 정량으로 계산돼 중복. 우리가 못 가진 정보는 품질뿐
  - 별점 5점이 아니라 3단계. 서비스 성격이 가격 비교에서 가게 리뷰로 바뀌는 것을 막고, 5점 척도는 모바일에서 정확히 누르기 어려움

- 결정 필요
  - 직접 입력한 가게명은 여전히 자유 텍스트라 같은 가게가 다른 표기로 갈라질 수 있음. 제보 집계와 같은 사안

#### 야채 검색

- 해결하는 문제 — 9종일 때는 눈으로 탐색 가능했으나 46종에서는 정확한 이름 입력이 병목. 고춧가루 국산처럼 긴 이름은 검색으로 도달 곤란

  - 초성 입력에 이름 매칭까지 병행하면 자음 한 글자에 다수가 걸려 결과 무의미

  - 결과 부재 시 빈 상태
  - 눈에 보이는 라벨 필요. 안내 문구만 두면 입력 후 해당 칸의 용도가 화면에 미표시

- 결정 필요
  - 유사 품목 구분 표기 방식. 규격 단계에서 별개 품목으로 분리된 쌍들 — 대파와 쪽파, 적상추와 청상추, 애호박과 쥬키니, 방울토마토와 대추방울토마토, 고춧가루 국산과 중국산. 이름만으로는 차이가 안 읽힘

  - 검색 중에는 종류 칩 숨김

  - 분류 기준의 실제 장보기 감각 부합 여부. 현재는 장 볼 때 묶는 방식으로 임의 분류

- 해결하는 문제 — 자주 사는 품목의 반복 탐색

- 동작
  - 그리드 또는 시세 화면에서 토글
  - 찜한 야채는 즉석 판단 품목 선택에서도 우선 노출
  - 별도 등록 없이 알림의 대상이 됨. 찜 = 구독. 최근 평균 대비 의미 있게 하락하면 알림 다이제스트에 포함(「알림」 참조)

- 화면 요소
  - 찜 부재 시 빈 상태 문구

#### 홈 시세 표시

- 정의 — 홈 목록 각 칸에 오늘 시세와 어제 대비 등락 표시
- 해결하는 문제 — 홈에 야채 그림만 있어 조회 대상 선택 정보 부재. 품목마다 진입 필요

- 동작
  - 어제와 오늘 비교
  - 0.5% 미만 변화는 변동 없음으로 처리. 매일 소액에 화살표가 뒤집히면 신호가 아니라 잡음
  - 기본 12종만 노출하고 더보기로 전체 46종. 정렬은 가나다·싼 순·많이 내린 순이며 정렬을 바꾸면 다시 12종으로 접힘

- 화면 요소
  - 상승은 빨강, 하락은 초록. 구매자 기준
  - 화살표 단독 전달 금지
  - 46종을 한 번에 쏟지 않음. 3열이면 16줄이라 홈이 그리드에 잠기고 정렬도 바꿀 수 없었음
  - 시세 기준일 표시. 공공 시세가 더미로 폴백된 경우 그 사실도 함께 노출. 폴백은 인증키 미설정·API 실패·휴일 데이터 부재에 조용히 일어나 진짜와 구분 불가였음
  - 그리드는 개인화 카드보다 위. 조건부 카드가 위에 있으면 신규 사용자는 상단이 비고 헤비 사용자는 주 콘텐츠가 첫 화면 밖으로 밀림

- 결정 필요
  - 등락 기준. 어제 대비 또는 주간 평균 대비
  - 정렬 UI 형태. 현재는 칩. 디자인 시스템에 select 컴포넌트가 없어 임의로 만들지 않았고 드롭다운이 맞는지 미정

#### 온보딩

- 정의 — 첫 진입에 닉네임과 행정동을 받아 이후 이웃으로 표시. F00
- 해결하는 문제 — 제보에 소속감·권위 부여. 동네 확정이 나머지 기능의 전제

- 동작
  - 카카오 목업 인증 후 닉네임 입력. 2~8자 필수, 오류는 입력창 아래에 노출, 엔터로 다음 단계
  - 동네 이름 검색 또는 근처 동네 5개에서 한 곳을 선택하고 「확인」으로 확정
  - 지역 확정 후 별도 환영 화면 없이 홈 이동

- 화면 요소
  - 진입 즉시 자동 측위 금지. 권한 팝업으로 플로우를 막지 않고 저장된 동네 또는 기본 앵커를 기준으로 추천
  - 검색어 없을 때는 가까운 5개만 추천. 전체를 쏟으면 고르는 게 아니라 훑는 일이 됨
  - 지금 있는 동네라는 문구는 위치를 실제로 알 때만. 모를 땐 폴백 기준이라 다른 문구 사용
  - 동 단위 선택. 구 단위는 우리 동네 체감 미형성
  - 지역 목록은 서울 424개 행정동 실좌표 + 경기 주요 동. 온보딩·홈 동네 전환·설정이 같은 컴포넌트 사용

- 결정 필요
  - 닉네임 중복 확인 (백엔드 필요)

#### 첫 제보 안내

- 정의 — 제보 이력 0건 사용자에게만 홈에서 첫 제보 권유
- 해결하는 문제 — 온보딩 완료 후에도 제보 이유가 없으면 조회만 하고 종료

- 동작
  - 내 제보 0건 시 안내 카드 노출
  - 우리 동네 제보 건수 병기. 이미 사용 중인 동네이거나 내가 첫 번째라는 두 가지 중 하나로 동기 형성

  - 제보 1건 이상 사용자에게는 숨김. 잔존 시 잔소리로 인식

#### 데이터 전제

- 비교 기준 시세는 서버에서 전달. 제보는 기기에 저장돼 목록은 화면에서 생성. 기준까지 화면에서 임시값으로 계산하면 실제 시세 연결 시 숫자 불일치. 품목별 시세 대응표를 서버에서 생성해 순위·가게 목록·가게 상세·즉석 판단이 동일 값 사용
- 기준일도 서버에서 전달. 제보 최신도·주간 절약이 기기 시계에 흔들리지 않게
- 이웃 제보 예시 데이터는 동네별 필요 시 생성. 46종에 100여 개 동을 전부 미리 만들면 1만 건 초과로 렌더 비용 증가
- 홈은 46종 기준값을 서버에서 일괄 집계 후 요약만 전달. 기간별 값 전량은 약 2,200개 지점으로 전송량 과다
- 시세 캐싱은 1시간 단위 재검증. 원본이 하루 1회 갱신
- 인증키는 서버 전용. 화면 코드에서 격리. 지도 앱키만 예외로 브라우저에 노출되는데, 도메인 제한이 걸리는 공개 키라 비밀값이 아님
- 가게 좌표는 제보에 실려 오지 않음. 동 중심에 가게명 해시 오프셋을 더해 결정적으로 생성하므로 매 렌더 같은 자리. 실서비스에서는 장소 검색 좌표로 교체
- 동네 댓글도 동네별·품목별로 필요 시 생성. 제보와 같은 이유

#### 결정 필요 목록

데이터 정확성 사안이 위. 틀리면 화면이 조용히 잘못된 값을 노출한다.

- 1순위 — 1단·1망 환산 계수 실측. 현재 단 0.8kg·망 1.5kg 가정. 지역·품목마다 달라 이 값이 틀리면 판정 전체가 틀림
- 2순위 — 판정 기준 8%, 이상치 3배·3분의 1, 오래됨 7일의 적정성. 전부 근거 없는 초기값
- 3순위 — 온라인 4채널 연결 방법과 갱신 주기. 몰마다 검색 URL·상품 코드 수명·판매자별 편차가 달라 일괄 처리 불가
- 알림 트리거 임계값. 찜한 야채 가격 하락 10%(최근 30일 평균 대비), 단골 가게 새로 올라온 제보 기준일수 1일. 둘 다 근거 없는 초기값
- 다이제스트의 지역 범위. 동네를 최대 3개 등록할 수 있는데 현재 미리보기는 활성 동네 1곳만 계산한다. 등록 동네 전체를 묶을지 활성 1곳만 볼지 미정
- 알림 발송 인프라 도입 시점
- 홈 단골집 카드 존치 여부. 가게 탭과 축이 같아져 중복
- 지도 앱키 발급. 미설정 시 가게 상세에서 지도 없이 주소와 거리만 노출
- 허위 제보 신고·제재 기준. 현재는 이상치 표시까지만
- 가게 단위 비공개 옵션. 가게 사장 반발 시
- 방울토마토·대추방울토마토 화면 표기. 개 단위가 맞지만 개당 수백 원이라 어색함
- 심부름 목록 재도입 여부. 대리 구매자 문제는 선명했으나 장바구니 배제로 입력이 사라짐
- 실서비스 집계 주기. 싼 가게·최저가 품목·제보왕 순위 공통. 실시간 또는 일 1회
- 이번 달 최저가 품목 채택 기준 6위·2%. 섹션이 사라지지 않게 푼 임시값이라 근거 없음
- 근처 가게 검색 반경 2km. 마찬가지로 초기값
- 제보 수정 이력 보존 여부. 현재는 덮어쓰기라 이웃이 이미 본 값이 조용히 바뀜
- 동네 복수 등록 사용자에게 제보·시세를 합쳐 보여줄지. 현재는 등록만 여러 개고 활성은 하나
- 홈 그리드 정렬 UI 형태. 디자인 시스템에 select가 없어 칩으로 대체한 상태
- 가게명 표기 정규화. 직접 입력 경로가 자유 텍스트라 같은 가게가 갈라짐. 제보 집계와 신선도 후기에 공통
