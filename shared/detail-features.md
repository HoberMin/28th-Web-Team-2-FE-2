## 메인 기능

#### 공공 시세 조회(KAMIS)

정의: KAMIS 채소 데이터 규격(46종) 기준으로 오늘 시세·평균가·기간별 추이를 제공한다.

해결하는 문제: 판단 기준선이 없어 감으로 사고파는 문제.

프로세스:
1. 품목·대표 kindCode·등급(04)로 KAMIS 조회. 인증키 없으면 더미 시세로 폴백
2. 배추·무는 계절형 로직으로 살아있는 품종만 평균
3. 오늘 시세·평균가·기간별(1주/1개월/1년) 시리즈 반환
4. 온라인가(컬리·쿠팡 등)와 나란히 표시

화면 요소: 시세 없는 품목(비수기 등)은 빈 상태 문구 필요. 데이터 에러 시 폴백 표시

결정 필요: 46종 각각의 등급 코드가 실제로 맞는지 최종 검증 필요

#### 이웃 제보가

정의: 이웃이 사진 또는 직접 입력으로 올린 실제 목격 가격을 동네 단위로 모아 보여준다.

해결하는 문제: 공공 시세가 시·도 단위까지만 나와 동네 가격을 알 수 없는 문제.

프로세스:
1. 제보 방식 선택(촬영/직접입력)
2. 가게 위치 선택(GPS+Kakao 검색, 미등록 시 직접입력)
3. 품목·양·가격 입력(촬영 시 프리필)
4. 구매 여부 선택
5. 제출 → 제보 완료 화면 → 동네 제보가 목록에 반영

화면 요소: 제보 없는 동네는 빈 상태. 목록엔 구매·시세만 봄 배지, 시세 대비 차이 표시

결정 필요: 허위 제보 신고·제재 기준을 둘지

#### 시세 그래프(기간 전환)

정의: 품목별 시세를 1주·1개월·1년 단위로 전환해 보여주는 그래프.

해결하는 문제: 판단 근거가 기억뿐이라는 문제. 과거 추이로 보완한다.

프로세스:
1. 기간 탭 선택(1주/1개월/1년)
2. 해당 기간 시리즈 조회
3. 그래프 렌더링, 포인트 터치 시 날짜별 가격 표시

화면 요소: 데이터 부족한 구간은 빈 구간으로 표시(끊긴 그래프와 구분되게)

결정 필요: 데이터 없는 구간을 시각적으로 어떻게 표현할지

#### 찜하기 + 야채 검색

정의: 46종 중 관심 품목을 찜해두거나 이름으로 검색해 빠르게 찾는다.

해결하는 문제: 46종을 그리드로만 보면 원하는 걸 찾기 오래 걸리는 문제.

프로세스:
1. 그리드에서 하트 아이콘으로 찜 토글, 또는 검색창에 이름 입력
2. 찜 목록·검색 결과 즉시 반영

화면 요소: 찜한 게 없으면 빈 상태 문구. 검색 결과 없을 때도 빈 상태 필요

결정 필요: 이름 비슷한 품목(대파/쪽파 등)을 검색에서 어떻게 구분해 보여줄지

## 해결장치(부가기능)

#### 온라인가 비교

정의: 컬리·쿠팡 등 온라인몰 가격을 크롤링해 공공시세·이웃 제보가 옆에 나란히 보여준다.

해결하는 문제: 시·도 단위 공공시세만으론 채널별 가격차를 못 보여주는 문제.

프로세스:
1. 여러 온라인몰 정기 크롤링
2. 품목별 가격 매칭·저장
3. 시세 화면에 공공시세·제보가와 나란히 표시

화면 요소: 크롤링 안 된 품목은 온라인가 항목 자체를 숨김. 프리미엄 채널이라 비쌀 수 있다는 걸 라벨로 표기

결정 필요: 크롤링 갱신 주기를 얼마로 할지

#### 소비 요약·절약 계산

정의: 구매로 표시된 제보만 모아 그날 시세와 비교해 절약·초과 금액을 계산해 보여준다.

해결하는 문제: 사고 나서 잘 산 건지 모른다는 문제. 제보할 유인도 없다.

프로세스:
1. 구매 표시된 제보 조회
2. 그날 대표 시세와 비교
3. 절약·초과 금액 계산
4. 화면에 표시

화면 요소: 구매 0건이면 "야채를 사고 가격을 제보하면 시세보다 얼마나 아꼈는지 알려드려요" 빈 상태 문구. 절약이면 초록, 초과면 주황 색 구분

결정 필요: 절약액이 마이너스(초과)일 때 문구 톤을 어떻게 할지

#### 온보딩(닉네임+동네)

정의: 첫 진입 시 닉네임과 동네(자치구)를 입력받아 이후 이웃으로 표시한다.

해결하는 문제: 제보할 유인이 없다는 문제. 소속감과 권위를 부여한다.

프로세스:
1. 닉네임 입력
2. GPS로 동네 자동 감지, 필요 시 수동 보정
3. 완료(웰컴) 화면 표시
4. 홈으로 이동

화면 요소: GPS 거부 시 수동 선택 화면 필요

결정 필요: 닉네임을 필수로 할지 선택으로 할지

#### 촬영 제보

정의: 사진을 찍어 제보하면 품목·양·가격을 프리필해 30초 안에 제보를 끝낸다.

해결하는 문제: 허위·장난 제보를 못 거르는 문제. 사진으로 신뢰도를 높인다.

프로세스:
1. 카메라 열기(권한 거부 시 에러 상태로 전환)
2. 셔터로 프레임 고정
3. 품목·양·가격 프리필 확인
4. 구매 여부 선택 후 제출

화면 요소: 카메라 권한 거부 시 대체 문구와 직접입력 유도

결정 필요: 실제 이미지 인식을 언제부터 붙일지(지금은 시뮬레이션)

#### 정확한 위치 찍기(GPS + Kakao 검색)

정의: GPS 좌표로 근처 청과물·마트를 Kakao 키워드 검색으로 찾아 제보 위치를 자치구보다 좁게 특정한다.

해결하는 문제: 구 단위로 받아도 동네 단위보다 넓어 문제가 안 풀리는 문제.

프로세스:
1. GPS 좌표 확인
2. Kakao 키워드 검색(반경 내 "청과"·"채소"·"과일" 포함 장소). API 키 없으면 더미 가게 목록으로 폴백
3. 목록에서 선택, 미등록 시 직접 입력

화면 요소: 근처에 검색 결과 없으면 바로 직접 입력 폼으로 전환

결정 필요: 반경을 몇 m로 잡을지. Kakao 실연결 시점

#### 구매 장소 공개

정의: 동네 제보가 목록의 각 행에 제보자가 다녀온 가게명을 함께 노출한다.

해결하는 문제: 제보 목록만 봐서는 "같은 동 사람들"이라는 신뢰·소통이 생기지 않는 문제.

프로세스:
1. 제보 시 가게 위치 선택(F04-1)에서 넘어온 place를 제보에 저장
2. 동네 제보가 목록 각 행에 날짜 아래 가게명 서브텍스트로 표시

화면 요소: place 없는 제보(직접 위치 미지정)는 서브텍스트 생략

결정 필요: 가게 사장님 반발 시 비공개 옵션을 둘지(이웃 제보가 리스크와 동일 이슈)

#### 동네 댓글

정의: 동네 제보가 아래에 같은 동 이웃끼리 댓글을 남긴다.

해결하는 문제: 제보가 일방향 데이터라 이웃 간 소통·신뢰가 안 쌓이는 문제.

프로세스:
1. 시세 화면 하단 댓글 목록 확인(같은 동·같은 품목만)
2. 닉네임+내용 입력 후 등록

화면 요소: 댓글 없으면 "아직 댓글이 없어요" 빈 상태

결정 필요: 구매인증(실제로 산 사람만 댓글 가능) 게이트를 둘지

#### 뱃지

정의: 제보·구매 건수가 일정 기준을 넘으면 마이페이지에 단계별 뱃지를 표시한다.

해결하는 문제: 제보할 유인이 없다는 문제(구매인증 원동력).

프로세스:
1. 마이페이지 진입 시 내 제보·구매 건수 집계
2. 기준(1/5/15건 제보, 3건 구매) 통과 여부로 뱃지 획득 표시

화면 요소: 미획득 뱃지는 흐리게(반투명) 표시해 다음 목표를 알려줌

결정 필요: 뱃지 종류·기준을 실사용 데이터로 재조정할지

#### 가격 알림 설정

정의: 찜한 야채마다 가격 알림을 켜고 끄는 설정을 마이페이지에 둔다(실제 발송 없음, 예시 UI).

해결하는 문제: 매번 시세를 확인하러 앱을 켜야 한다는 문제.

프로세스:
1. 마이페이지에서 찜한 야채별 토글 on/off

화면 요소: 찜한 야채 없으면 "찜한 야채가 있으면 알려드려요" 안내, 예시 기능임을 라벨로 명시

결정 필요: 실제 푸시 발송 인프라(FCM 등) 도입 시점과 알림 기준(하락폭 %)

#### 월별 최저가 시기

정의: KAMIS 실시세 12개월 평균 시리즈에서 가장 쌌던 달을 계산해 시세 화면에 표시한다.

해결하는 문제: "언제 사는 게 싼지" 판단할 근거가 없는 문제.

프로세스:
1. 연 시리즈(월평균) 중 최저가 달 계산
2. 최신 달 대비 몇 % 더 쌌는지 계산해 함께 표시
3. KAMIS 미연결(더미 시리즈)이면 "예시" 라벨을 붙여 실데이터와 구분

화면 요소: 최저가가 최신 달보다 안 싸면(0% 이하) 배지 자체를 숨김

결정 필요: 식물학적 제철 데이터를 별도로 병기할지(지금은 순수 계산값만)

#### 랭킹(동네 최저가 · 제보왕)

정의: 동 단위로 오늘 최저가 Top 5, 이번 주 제보왕 리더보드 두 탭을 보여준다.

해결하는 문제: 시세 화면만 봐서는 앱을 계속 켜볼 이유가 약한 문제(재방문 동기).

프로세스:
1. 탭 전환(최저가 순위 / 제보왕)
2. 목록 표시, 최저가 항목은 품목 시세 화면으로 연결

화면 요소: 전부 예시 데이터 — "예시 데이터입니다 · OO동 기준" 명시

결정 필요: 실서비스 전환 시 집계 주기(실시간/일배치)

#### 장바구니(장보기 전 예산 계획)

정의: 살 품목+수량(kg)만 담아 KAMIS 시세 기준 예상 총액과 동네 최저 제보가 기준 예상 총액을 비교한다.

해결하는 문제: 품목 화면을 하나씩만 보면 "오늘 장보기 전체 예산"을 가늠하기 어려운 문제.

프로세스:
1. 시세 화면 또는 장바구니 화면 자체(바텀시트 그리드·찜 퀵애드)에서 담기
2. 담은 품목의 수량 조절·삭제
3. 두 기준(KAMIS/동네 최저가) 총액과 차액(절약 예상) 표시
4. 각 행 "제보하러 가기"로 실제 이웃 제보가 플로우 연결

화면 요소: 빈 상태 "아직 담은 야채가 없어요"(+ 찜한 야채 있으면 퀵애드 그리드 노출)

결정 필요: 장바구니 자체에 구매 확정(체크아웃) 액션을 추가할지, 지금처럼 계획 전용으로 남길지
