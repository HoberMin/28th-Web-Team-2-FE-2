#### 세부기능 정의서

- 동네 야채 시세 서비스 세부기능 32개 정의
- 기획·디자인·개발 공통 참조 문서
- 2026-07-30 기준 (기능 다이어팅 반영)

#### 참조 문서

- 46종 품목·품종·등급·단위 규격 → `kamis-vegetable-data-spec.md`. 품목 스코프와 API 파라미터의 진실 소스이며, 이 문서는 규격값을 복제하지 않고 참조만 한다
- 화면 단위 목록 → `pages.md`
- 정책·엔티티 → `domain.md` / 코딩 규약 → `conventions.md`

#### 문서 규격

- 기능마다 다섯 항목 — 정의 / 해결하는 문제 / 동작 / 화면 요소 / 결정 필요
- 데이터 규격에 의존하는 기능은 참조 항목을 추가로 둔다
- F00~F12는 화면 번호. 화면 단위 목록은 페이지 목록 문서
- 일부 기능은 화면만 구현된 상태. 프로토타입 화면에는 예시 라벨을 노출하지 않는다 — UT에서 실제 서비스처럼 판단하게 하기 위함이며, 어느 값이 실측인지는 이 문서가 진실 소스다
- 기능 순서는 사용자 여정 순 — 기준 가격 → 동네 실제가 → 구매 판단 → 매장 선택 → 기록·재방문 → 탐색·진입

#### 기능 목록

- 기준 가격 5개 — 공공 시세 조회, 시세 그래프, 월별 최저가 시기, 이번 달 최저가 품목, 온라인가 비교
- 동네 실제가 6개 — 이웃 제보가, 촬영 제보, 가게 위치 특정, 제보 신뢰 표시, 구매 장소 공개, 근처 동네 가격
- 구매 판단 4개 — 즉석 판단, 시장 단위 환산, 가게 상세, 싼 가게 순위
- 매장 선택 1개 — 매장 목록
- 기록·재방문 10개 — 소비 요약, 주간 절약, 재구매 주기, 매장 알림, 뱃지, 단골 가게, 최저가 품목 순위, 제보왕 순위, 동네 댓글, 카드뉴스
- 탐색·진입 6개 — 야채 검색, 종류별 필터, 찜하기, 홈 시세 표시, 온보딩, 첫 제보 안내

#### 설계 기준

- 판단은 3초 이내 완료. 사용자가 앱을 켜는 순간은 매장 가격표 앞이고, 그 자리에서 안 끝나는 기능은 정확해도 안 쓰임
- 답은 품목이 아니라 가게 단위. 사용자의 질문은 감자 가격이 아니라 오늘 갈 가게. 품목별 최저가만 주면 가게가 흩어져 발걸음 증가
- 절약액과 발걸음 동시 노출. 돈만 아끼게 하면 노력 절약을 잃음. 선택은 사용자 몫
- 제보는 장보기의 부산물. 따로 요청하면 안 함. 판단하려고 이미 넣은 가격을 그대로 제보로 전환
- 근거 없는 숫자 금지. 기준 없으면 판정 보류, 낡은 제보는 낡음 표시
- 계획이 아니라 선택을 돕는다. 살 목록을 담아두는 기능은 찜하기와 구별되지 않아 배제. 사용자의 질문은 무엇을 담았나가 아니라 오늘 어느 가게 갈까

#### 공공 시세 조회

- 정의 — 농산물유통정보 46종의 오늘 시세·평균가·기간별 추이 제공
- 해결하는 문제 — 판단 기준선 부재. 감에 의존한 구매

- 참조 — 품목코드·품종코드·등급코드·단위는 전부 `kamis-vegetable-data-spec.md` v3가 진실 소스. 이 문서에 코드값을 복제하지 않는다. 스코프는 채소류와 특용작물이며 축산물·수산물은 제외, 과일 중 수박·참외·멜론·딸기는 규격상 채소류로 분류돼 포함

- 동작
  - 매 요청에 파라미터 4개를 전부 명시. 품목분류·품목·품종·등급
  - 등급은 상품 고정. 스코프 전 품목에서 연중 존재함을 실측 확인했고, 중품은 표본이 얇아 며칠씩 값이 안 바뀌는 등 품질이 낮았음
  - 단위는 품목별 분기. kg·g 품목은 kg 환산 요청, 개·포기 품목은 환산 없이 원 단위 유지. 오이는 kg 환산이 성립하지 않아 개수 단위
  - 배추·무는 품종이 아니라 계절로 갈림. 봄·여름고랭지·가을·월동을 전부 조회해 응답 있는 것만 평균. 달력으로 시즌 고정 금지
  - 오늘 시세·평균가·기간별 1주·1개월·1년 값 생성
  - 수박·참외·딸기·갓은 비수기 데이터 없음이 정상

- 화면 요소
  - 비수기 품목은 가격 대신 계절 문구로 대체
  - 조회 실패 시에도 화면이 비지 않게 대체값 표시
  - 유사 품목은 규격 단계에서 이미 분리됨. 애호박과 쥬키니, 대파와 쪽파, 적상추와 청상추, 방울토마토와 대추방울토마토, 고춧가루 국산과 중국산. 화면에서도 합치지 않는다

- 결정 필요
  - 방울토마토·대추방울토마토 화면 표기. 규격상 개 단위가 맞지만 개당 수백 원이라 화면에서 어색함. 팩 환산 표기 여부는 표시 층의 결정
  - 규격 문서가 v3에서 정리한 배제 품목이 늘거나 줄 때의 갱신 주체

#### 시세 그래프

- 정의 — 품목별 시세를 1주·1개월·1년으로 전환해 표시
- 해결하는 문제 — 판단 근거가 기억뿐. 과거 추이로 보완

- 동작
  - 기간 탭 선택 후 해당 기간 값 조회
  - 그래프 표시. 지점 선택 시 날짜별 가격 노출

- 화면 요소
  - 데이터 없는 구간은 선을 잇지 않고 비움. 0원과 구분 필요
  - 키보드로도 지점 이동 가능. 좌우 화살표로 한 칸, Home·End로 양 끝. 터치 전용이면 키보드 사용자는 최신 지점 하나만 확인 가능

- 결정 필요
  - 데이터 없는 구간의 시각 표현 방식

#### 월별 최저가 시기

- 정의 — 1년 월평균 중 최저 달을 찾아 시세 화면에 표시
- 해결하는 문제 — 구매 시점 판단 근거 부재

- 동작
  - 1년 월평균 중 최저 달 계산
  - 이번 달 대비 하락률 함께 표시

- 화면 요소
  - 최저 달이 이번 달보다 안 싸면 배지 숨김. 의미 없는 정보 미노출

- 결정 필요
  - 달력상 제철 정보 병기 여부
  - 이번 달 최저가 품목과 계산 근거가 같아 통합 여부 검토

#### 이번 달 최저가 품목

- 정의 — 1년 월평균에서 이번 달이 저점권 3위 이내인 품목만 홈 상단에 노출
- 해결하는 문제 — 계절별 저가 품목 파악 불가. 달력상 제철이 아니라 실시세 계산값

- 동작
  - 품목별로 이번 달의 1년 내 저가 순위 계산
  - 3위 이내 + 연 최고가 대비 5% 이상 저가인 품목만 채택. 근거가 얇으면 저가 표기 금지
  - 할인폭 큰 순으로 최대 6개. 가로 스크롤

- 화면 요소
  - 연 최고가 대비 하락률 + 근거 라벨
  - 해당 품목 없는 달에는 섹션 미노출

- 결정 필요
  - 월별 최저가 시기와 통합 여부

#### 온라인가 비교

- 정의 — 컬리·쿠팡·G마켓·B마트 가격을 판매 방식과 함께 표시. 오프라인 판단의 보조 기준
- 해결하는 문제 — 공공 시세만으로는 채널별 가격차 확인 불가

- 동작
  - 채널별 가격을 품목 기준 단위로 환산
  - 환산 불가 상품은 미포함. 억지 환산이 정보 부재보다 위험
  - 기본은 최저가 한 줄로 접힘. 오프라인 동네 가격이 화면의 주인
  - 펼치면 채널별 가격 + 판매 방식 + 단서. 방식은 새벽배송·당일배송·오픈마켓·즉시배송, 단서는 배송비 별도·회원가

- 화면 요소
  - 판매 방식 필수 표기. 즉시배송은 소량이라 구조적으로 고가, 오픈마켓은 배송비 별도. 방식 없이 금액만 줄 세우면 즉시배송이 제일 비싸다는 결론만 반복돼 정보량 0
  - 컬리만 실측, 나머지 3채널은 미연결 상태. 화면에는 라벨을 붙이지 않고 이 문서로 관리
  - 채널별 항목 선택 시 해당 몰 검색으로 이동. 상품 단위 딥링크는 상품 코드가 바뀌어 죽은 링크가 되므로 품목 검색으로 연결
  - 오프라인 동네 가격이 기준이고 온라인은 참고용임을 하단에 명시

- 결정 필요
  - 가격 갱신 주기
  - 채널별 연결 방법. 쿠팡은 자동 수집 차단, G마켓은 판매자별 편차, B마트는 앱 전용. 일괄 처리 불가

#### 이웃 제보가

- 정의 — 이웃이 올린 실제 목격 가격을 행정동 단위로 집계해 표시
- 해결하는 문제 — 공공 시세가 광역 단위까지만 나와 동네 가격 확인 불가. 서비스의 유일한 차별점

- 동작
  - 제보 방식 선택. 촬영 또는 직접 입력
  - 가게 위치 선택
  - 품목·양·가격 입력. 양의 단위는 품목별. 촬영·즉석 판단 경유 시 프리필
  - 구매 여부 선택. 구매 또는 목격
  - 제출 후 완료 화면. 동네 제보가 목록에 반영
  - 완료 화면에서 같은 가게의 다음 품목을 이어서 입력 가능. 가게명은 유지하고 품목만 교체

- 화면 요소
  - 연속 입력 경로 필수. 매장 축 화면이 성립하려면 한 가게에 여러 품목 제보가 있어야 함. 품목마다 제보 흐름을 처음부터 다시 타게 하면 가게마다 1~2건씩 흩뿌려져 이 가게가 전반적으로 싼가에 답할 수 없음
  - 목록 3열 — 제보일 / 오늘 시세와의 차이 / 가격
  - 위치 확인 중 안내는 입력값을 덮지 않고 안내 문구로만. 값을 치환하면 사용자가 먼저 적은 가게명이 사라짐
  - 시세 그래프보다 위에 배치. 그래프는 참고 자료이고 동네 제보가가 구매 판단의 직접 근거
  - 가게명 선택 시 해당 가게의 전 품목 가격으로 이동
  - 제보 없는 동네는 빈 화면 대신 근처 동네 가격 노출

- 결정 필요
  - 허위 제보 신고·제재 기준. 현재는 이상치 표시까지만

#### 촬영 제보

- 정의 — 사진 촬영으로 품목·양·가격을 프리필해 제보 시간 단축
- 해결하는 문제 — 허위·장난 제보 필터 부재. 사진으로 신뢰도 보강

- 동작
  - 카메라 실행
  - 셔터로 화면 고정
  - 인식 결과 확인
  - 구매 여부 선택 후 제출

- 화면 요소
  - 라이브 / 인식 중 / 오류 3가지 상태 필요. 오류는 권한 거부 상황
  - 카메라 권한 거부 시 직접 입력으로 유도
  - 촬영 진입 경로는 제보 방식 선택 화면 한 곳뿐

- 결정 필요
  - 실제 이미지 인식 도입 시점. 현재는 항상 감자로 인식되는 예시 동작

#### 가게 위치 특정

- 정의 — 현재 위치로 근처 청과물·마트를 찾아 제보 위치를 동보다 좁게 특정
- 해결하는 문제 — 동 단위로 받아도 가게 식별 불가

- 동작
  - 위치 확인
  - 근처 가게 검색. 청과·채소·과일 포함 상호
  - 목록에서 선택. 미등록 시 직접 입력

- 화면 요소
  - 검색 결과 없으면 직접 입력 폼으로 즉시 전환. 빈 목록 노출 금지

- 결정 필요
  - 검색 반경
  - 지도 서비스 연결 시점

#### 제보 신뢰 표시

- 정의 — 제보마다 신뢰 신호 3가지를 부착해 신뢰도 판단 지원
- 해결하는 문제 — 이웃 제보가가 유일한 차별점인데 검증 장치 부재. 틀린 제보 하나가 서비스 전체 신뢰를 훼손

- 동작
  - 최신도 — 오늘 / 어제 / N일 전. 1주일 초과 시 흐리게 처리하고 오래된 가격임을 명시. 야채 가격은 주 단위로 변동해 낡은 제보를 같은 무게로 노출하면 오판 유발
  - 교차 검증 — 같은 가게·같은 품목 제보 2건 이상이면 확인 인원 표시. 1건은 근거가 얇고 2건부터 상호 증인
  - 이상치 — 시세의 3배 초과 또는 3분의 1 미만은 오타·장난 확률 높음. 삭제하지 않고 목록 하단으로 이동, 확인 필요 표시, 평균 계산에서만 제외

- 화면 요소
  - 시세 화면 제보 목록과 가게 상세에 동일 규칙 적용

- 결정 필요
  - 이상치 기준 3배·3분의 1의 적정성
  - 오래됨 기준 7일의 품목별 차등 여부

#### 구매 장소 공개

- 정의 — 제보 목록에 방문 가게명 노출. 선택 시 가게 화면으로 이동
- 해결하는 문제 — 가격만으로는 방문할 가게를 알 수 없음. 가게 단위 조회의 입구 역할

- 동작
  - 제보 시 선택한 가게 저장
  - 목록에 가게명 표시
  - 선택 시 가게 상세로 이동

- 화면 요소
  - 가게 미선택 제보는 가게명 줄 생략

- 결정 필요
  - 가게 사장 반발 시 비공개 옵션 도입 여부

#### 근처 동네 가격

- 정의 — 우리 동네 제보 부재 시 가까운 동네 3곳의 가격을 출처와 함께 표시
- 해결하는 문제 — 제보 없는 동네는 화면 대부분이 빈 상태. 이웃 제보 기반 서비스의 첫 사용자가 반드시 만나는 상태이고, 빈 화면만 보면 데이터 없는 앱으로 판단하고 이탈

- 동작
  - 우리 동네 제보 0건 여부 확인
  - 거리순으로 훑어 제보 있는 동네 3곳 선정
  - 동네명·최신 가격·시세와의 차이·최신도 노출

- 화면 요소
  - 우리 동네 값이 아님을 문구로 명시. 정확도는 낮아도 출처를 밝히면 오해 없고, 아무것도 없는 상태보다 유용

- 결정 필요
  - 거리 상한
  - 근처 동네 값의 판정 기준 활용 여부. 현재는 표시만

#### 즉석 판단

- 정의 — 품목·단위·가격 입력만으로 우리 동네 기준 사도 좋음 / 적당함 / 비쌈 세 가지 중 하나를 한 화면에 표시. F10
- 해결하는 문제 — 매장 가격표 앞에서 앱을 켜는데 홈·검색·품목·시세 화면을 여러 번 스크롤해야 판단 완료. 판단까지의 거리가 과다

- 동작
  - 홈 최상단 또는 시세 화면에서 진입
  - 품목 선택. 찜한 야채와 자주 찾는 야채 우선 노출, 검색 병행
  - 파는 단위 선택. 1kg·1단·1망·1박스 등. 환산은 앱 처리
  - 가격 입력. 입력 중 실시간 판정
  - 판정 후 제보 연결. 입력값 그대로 제보로 이월

- 판정 기준
  - 우리 동네 최저 제보가 존재 시 그 값을 기준으로 사용. 같은 동네에서 그 가격에 산 사람이 있다는 사실이 더 강한 근거
  - 최저 제보가 부재 시 오늘 공공 시세를 기준으로 사용
  - 기준 대비 8% 이상 저가는 초록, 8% 이상 고가는 빨강, 사이는 노랑

- 화면 요소
  - 판정 카드는 결론 → 근거 → 다음 행동 순서. 비교 대상인 기준 가격과 제보 건수 명시
  - 색 단독 전달 금지. 문구가 결론을 그대로 진술
  - 표식은 아이콘. 색과 기호의 뜻을 일치시킴. 이모지는 기기·폰트마다 다르게 렌더링돼 디자인 통제 불가
  - 시세 데이터 없는 품목은 판정 보류 후 제보 유도
  - 하단 버튼은 항상 자리 유지, 비활성 상태로 노출. 판정 시점에 버튼이 새로 나타나면 입력 중 화면 이동 발생

- 결정 필요
  - 8% 기준의 적정성
  - 품목별 차등 여부

#### 시장 단위 환산

- 정의 — 시장 판매 단위 1단·1망·1박스·묶음을 비교 가능한 기준 단위로 환산
- 해결하는 문제 — 46종의 기준 단위가 kg·g·개·포기로 갈리고 시장은 kg 판매가 드묾. 환산 없이는 비교 자체가 불가

- 참조 — 품목별 기준 단위는 `kamis-vegetable-data-spec.md`의 단위 열. 이 값이 환산의 도착점이라 임의로 바꾸면 시세와 제보가가 다른 축에서 비교됨

- 동작
  - 품목 단위에 맞는 후보 제시. kg 품목은 1kg·1단·1망·1박스, 개 품목은 1개·3개 묶음·1봉지
  - 사용자가 판매 단위 선택 후 그 단위의 가격 입력
  - 기준 단위로 환산하고 환산 근거를 문구로 노출

- 화면 요소
  - 즉석 판단과 제보 폼에 단위 선택 필요

- 결정 필요
  - 1단·1망 환산 계수. 현재 단 0.8kg·망 1.5kg 가정. 지역·품목마다 달라 실측 필요. 이 값이 틀리면 판정 전체가 틀림

#### 가게 상세

- 정의 — 한 가게의 전 품목 가격을 한 화면에 집계. F09
- 해결하는 문제 — 전 화면이 품목 단위라 방문할 가게에 답하는 화면 부재. 서비스가 풀려는 문제인 가게 비교에 정면으로 답하는 화면

- 동작
  - 싼 가게 순위, 제보 목록의 가게명, 홈 단골집 카드에서 진입
  - 제보를 가게별로 집계. 같은 품목은 최신 1건을 대표로 채택. 가격은 시간에 민감
  - 시세 대비 저가 품목 순 정렬. 방문 이유가 먼저 읽혀야 함
  - 우측 상단에서 단골 등록

- 화면 요소
  - 요약 한 줄 — 제보 품목 수, 시세보다 싼 품목 수, 최근 제보 시점
  - 위치를 가격 목록보다 먼저 배치. 갈 만한 거리인가가 정해져야 가격을 볼 이유가 생김. 지도, 주소, 내 위치에서의 거리와 도보 시간
  - 좌표는 제보에 실려 오지 않음. 동 중심에 가게명 해시 오프셋을 더해 결정적으로 생성. 실서비스에서는 장소 검색 좌표로 교체
  - 지도는 지도 앱키가 있을 때만 렌더. 없으면 주소와 거리만 남기고 화면은 깨지지 않음
  - 섹션 제목은 이 가게에 제보된 가격. 가게가 게시한 공식 가격표가 아니라 이웃이 보고 남긴 값이라, 이름이 출처를 숨기면 틀린 값의 책임이 가게로 감
  - 품목마다 최신도·확인 인원·이상치 표시
  - 제보 없는 가게도 위치는 노출. 그 화면에서 유일하게 확실한 정보
  - 뒤로가기는 진입 경로로 복귀. 여러 경로에서 들어오는 화면이라 목적지 고정 시 오작동

- 결정 필요
  - 가게 단위 비공개 옵션. 구매 장소 공개와 동일 사안

#### 싼 가게 순위

- 정의 — 우리 동네 가게를 시세 대비 평균이 낮은 순으로 정렬
- 해결하는 문제 — 품목별 최저가만 제시하면 가게가 흩어짐

- 동작
  - 시세 대비 평균 저가 순 정렬
  - 동일 시 제보 많은 순. 근거가 두꺼운 쪽 우선

- 화면 요소
  - 가게별 제보 부재 시 빈 상태 + 제보 시 가게 선택 유도

- 결정 필요
  - 실서비스 집계 주기. 실시간 또는 일 1회

#### 매장 목록

- 정의 — 동네 매장을 시세 대비 편차 평균이 낮은 순으로 나열. 상단은 내 단골 가게. F07
- 해결하는 문제 — 전 화면이 품목 축이라 방문할 가게를 고르는 화면 부재. 사용자의 질문은 감자 가격이 아니라 오늘 갈 가게

- 동작
  - 현재 동의 제보를 가게별로 집계
  - 순위 기준은 시세 대비 편차 평균. 제보가 단순 평균이 아님. 매장마다 제보된 품목 구성이 달라 금액을 그대로 평균하면 비싼 품목이 많이 제보된 매장이 무조건 비싸 보이고, 매장이 아니라 품목 구성을 비교하게 됨
  - 동일 시 제보 많은 순. 근거가 두꺼운 쪽 우선
  - 줄에서 바로 단골 등록·해제. 화면 이동 없이 여기 자주 가는 데야를 남길 수 있어야 함
  - 단골로 등록한 가게는 상단으로 분리

- 화면 요소
  - 줄마다 시세 대비 평균, 거리와 도보 시간, 제보 품목 수, 최신도
  - 단골 0개여도 하단 동네 목록이 화면을 채움. 첫 사용자에게 빈 탭을 주지 않음
  - 절약액과 발걸음 동시 노출. 싼 것만 보여주면 발걸음이 늘어 절약이 상쇄됨
  - 랭킹의 싼 가게 탭과 같은 줄 컴포넌트 사용. 두 화면에 같은 마크업을 복붙하면 규칙이 갈림

- 결정 필요
  - 홈 단골집 카드와의 중복 처리. 축이 같아져 홈 카드를 남길지 미정
  - 랭킹 탭의 싼 가게와 병존 유지 여부. 현재는 양쪽 모두 노출

#### 소비 요약

- 정의 — 구매분만 집계해 그날 시세와 비교, 절약·초과 금액 산출
- 해결하는 문제 — 구매 후 적정성 판단 불가. 제보 유인도 여기서 발생

- 동작
  - 구매 표시 제보 조회
  - 그날 시세와 비교
  - 절약·초과 산출 후 마이페이지 상단 고정

- 화면 요소
  - 구매 0건이면 제보 시 절약액 확인 가능함을 안내
  - 절약은 초록, 초과는 주황

- 결정 필요
  - 초과 시 문구 톤. 비난으로 읽히지 않는 표현

#### 주간 절약

- 정의 — 최근 7일 구매만 집계해 주간 절약액과 최우수 구매 품목 표시
- 해결하는 문제 — 누적 요약은 첫 달 이후 숫자가 커져 변화 체감 불가. 장보기는 주 단위 리듬이라 주간이 체감 단위

- 동작
  - 최근 7일 구매 집계
  - 절약 합계 산출
  - 절약액 최대 품목을 최우수 구매로 지목

- 화면 요소
  - 칭찬 대상 구체화 필요. 품목명·금액·가게명 동시 노출
  - 이번 주 구매 부재 시 미노출

- 결정 필요
  - 주 시작 기준. 월요일 고정 또는 최근 7일. 현재는 최근 7일

#### 재구매 주기

- 정의 — 구매 간격에서 재구매 시점을 추정해 홈에서 안내
- 해결하는 문제 — 시세 확인을 위해 매번 앱 실행 필요

- 동작
  - 품목별 구매 간격 평균을 주기로 사용
  - 이력 1건이면 근거 부재로 14일 기본값 사용. 가정임을 문구로 명시
  - 주기 초과 품목만 경과일 순으로 최대 4개

- 화면 요소
  - 마지막 구매 경과일과 평균 주기 병기
  - 해당 품목 부재 시 미노출

- 결정 필요
  - 매장 알림과 역할 분담. 양쪽 다 재방문 시점을 만드는 장치라 둘이 같은 날 겹쳐 뜨면 잔소리로 읽힘

#### 매장 알림

- 정의 — 단골 가게별 알림 토글. 그 가게에 더 싼 제보가 올라오면 알림. 화면만 구현, 실제 발송 없음
- 해결하는 문제 — 시세 확인을 위해 매번 앱 실행 필요. 품목별 알림은 받아도 그래서 어디로 가지가 남아 행동으로 이어지지 않음

- 동작
  - 마이페이지에서 단골 가게별 토글

- 화면 요소
  - 단골 가게 부재 시 등록 유도 문구
  - 알림 개념은 하나만 유지. 품목 알림과 가게 알림 두 체계를 배우게 하지 않음

- 결정 필요
  - 알림 트리거 기준 미정. 그 가게 기존 최저가 갱신 또는 시세 대비 일정 비율 이상 저가 중 택. 전자는 자주 울리고 후자는 절대 기준이라 안정적
  - 발송 인프라 도입 시점

#### 뱃지

- 정의 — 제보·구매 건수 기준 통과 시 단계별 뱃지 부여
- 해결하는 문제 — 제보 유인 부재

- 동작
  - 제보·구매 건수 집계
  - 기준 통과 여부 판정. 제보 1·5·15건, 구매 3건

- 화면 요소
  - 미획득 뱃지도 흐리게 노출해 다음 목표 제시

- 결정 필요
  - 종류·기준의 실사용 데이터 기반 재조정 여부

#### 단골 가게

- 정의 — 자주 가는 가게를 등록해 매장 탭 상단과 홈에서 우선 확인
- 해결하는 문제 — 반복 구매가 타깃 특성인데 매번 가게 재탐색

- 동작
  - 등록·해제 지점 3곳 — 가게 상세 우측 상단, 매장 탭 목록의 줄, 랭킹 싼 가게 목록의 줄
  - 목록에서 바로 토글되어야 함. 등록하려고 상세로 들어갔다 나오게 하면 남기지 않음
  - 매장 탭 상단과 홈 요약 카드에 반영. 품목 수, 최근 제보 시점, 시세 대비 평균
  - 매장 알림의 대상 단위이기도 함

- 화면 요소
  - 단골 부재 시 홈 카드는 렌더 생략. 빈 카드로 홈 길이 증가 금지
  - 아이콘 단독 버튼이라 켜짐·꺼짐을 이름표로도 전달

- 결정 필요
  - 등록 개수 상한
  - 홈 요약 카드 존치 여부. 매장 탭과 축이 같아져 중복

#### 최저가 품목 순위

- 정의 — 동네에서 오늘 가장 싼 품목 순위
- 해결하는 문제 — 시세 화면만으로는 재방문 이유 부족

- 화면 요소
  - 기준 동네 명시

- 결정 필요
