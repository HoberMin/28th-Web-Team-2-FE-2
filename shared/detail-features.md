세부기능 정의서, 2026-07-30

동네 야채 시세 서비스의 기능 34개를 정의한다. 기획·디자이너·백엔드가 이 문서를 보고 의사결정한다.
전부 구현돼 있어 배포된 `/prototype`에서 동작을 확인할 수 있다.

## 이 문서 읽는 법

- 기능마다 **정의 / 해결하는 문제 / 동작 / 화면에서 챙길 것 / 정해야 할 것** 5칸으로 적는다.
- `F00`~`F12`는 **화면 번호**다. 화면 단위 목록은 `pages.md`에 있다.
- 기능은 만든 순서가 아니라 **목적별로** 묶었다(1~6장).
- 구현·백엔드 전제는 본문에 섞지 않고 맨 뒤 「개발 전제」에만 모았다.
- **"예시"라고 적힌 기능은 화면만 있고 실데이터가 없다.** UT에서 어디까지 보여줄지는 마지막 절 참고.

## 설계 원칙

기능을 넣을지 뺄지는 아래 5가지로 판단했다. 새 기능을 제안할 때도 같은 기준을 쓴다.

**① 판단은 3초에 끝나야 한다**
사용자가 앱을 정말 켜는 순간은 **매장 가격표 앞**이다. 그 자리에서 판단이 안 끝나는 기능은 아무리 정확해도 안 쓰인다.

**② 품목이 아니라 가게로 답한다**
사용자의 질문은 "감자가 얼마야?"가 아니라 **"오늘 어느 가게 갈까?"**다. 품목별 최저가만 알려주면 감자는 A가게, 오이는 B가게로 흩어져 발걸음이 늘어난다.

**③ 절약액과 발걸음을 함께 보여준다**
돈을 아끼려고 가게를 세 곳 돌게 만들면 "노력 절약"을 잃는다. 아끼는 금액과 들르는 가게 수를 나란히 두고 **선택은 사용자에게 맡긴다.**

**④ 제보는 장보기의 부산물이어야 한다**
제보를 따로 하라고 요청하면 안 한다. 판단을 위해 이미 가격을 입력했으니, 그 값이 그대로 제보가 되게 만든다.

**⑤ 모르는 건 아는 척하지 않는다**
비교 기준이 없으면 판정하지 않는다. 예시 데이터는 예시라고 적는다. 낡은 제보는 낡았다고 표시한다. 근거를 밝히지 않는 숫자는 신뢰를 못 얻는다.

## 1장 · 가격 기준 만들기

동네 가격이 싼지 비싼지 말하려면 **비교 대상**이 먼저 있어야 한다. 이 장의 기능들이 그 기준선을 만든다.

### 공공 시세 조회

**정의** 농산물유통정보(KAMIS) 46종의 오늘 시세·평균가·기간별 추이를 제공한다.

**해결하는 문제** 판단 기준선이 없어 감으로 사고파는 문제.

**동작**

1. 품목·품종·등급(상품)으로 조회한다.
2. 단위는 품목마다 다르다 — kg·g로 파는 품목은 kg로 환산하고, 개·포기로 파는 품목은 그 단위 그대로 쓴다.
3. 배추와 무는 품종이 아니라 **계절로 갈린다**(봄·여름고랭지·가을·월동). 4개를 전부 조회해 **응답이 있는 것만 평균**한다. 달력으로 시즌을 고정하지 않는다 — 지금 어느 시즌이 살아 있는지는 응답이 알려준다.
4. 오늘 시세·평균가·기간별(1주·1개월·1년) 값을 만든다.
5. 수박·참외·딸기·갓은 비수기에 데이터가 아예 없다. 오류가 아니라 정상이다.

**화면에서 챙길 것**

- 비수기 품목은 가격 대신 "여름 한정" 같은 문구로 대체한다.
- 조회가 실패해도 화면이 비지 않게 대체값으로 채우고, 실데이터가 아님을 표시한다.

**정해야 할 것**

- 46종 각각의 등급 코드가 맞는지 최종 검증. **틀리면 해당 품목이 조용히 빈 값으로 나온다.**
- 배추·무 계절 품종 4개의 실제 코드값(규격 문서에 없다).
- 방울토마토·대추방울토마토가 규격상 "개" 단위인데 개당 수백 원이라 화면에서 어색하다. 팩 단위가 맞는지 확인.

### 시세 그래프

**정의** 품목별 시세를 1주·1개월·1년으로 전환해 보여준다.

**해결하는 문제** 판단 근거가 기억뿐이라는 문제. 과거 추이로 보완한다.

**동작** 기간 탭 선택 → 해당 기간 값 조회 → 그래프 표시. 점을 누르면 날짜별 가격이 나온다.

**화면에서 챙길 것** 데이터가 없는 구간은 선을 잇지 않고 비워둔다. 값이 0원인 것과 구분돼야 한다.

**정해야 할 것** 데이터 없는 구간을 시각적으로 어떻게 표현할지.

### 월별 최저가 시기

**정의** 1년 월평균에서 가장 쌌던 달을 찾아 시세 화면에 알려준다.

**해결하는 문제** "언제 사는 게 싼지" 판단할 근거가 없는 문제.

**동작** 1년 월평균 중 최저 달 계산 → 이번 달 대비 몇 % 더 쌌는지 함께 표시.

**화면에서 챙길 것** 최저 달이 이번 달보다 안 싸면 배지를 아예 숨긴다. 의미 없는 정보를 남기지 않는다.

**정해야 할 것** 달력상의 제철 정보를 함께 보여줄지. 아래 「이번 달 사기 좋은 야채」와 계산 근거가 같아 통합할지.

### 이번 달 사기 좋은 야채

**정의** 1년 월평균에서 **이번 달이 저점권(3위 이내)**인 품목만 골라 홈 상단에 보여준다.

**해결하는 문제** "계절별로 뭐가 싼지" 알 방법이 없던 문제. 달력상의 제철이 아니라 **실제 시세로 계산한 값**이다.

**동작**

1. 품목별로 이번 달이 1년 중 몇 번째로 싼 달인지 계산한다.
2. 3위 이내 + 연 최고가보다 5% 이상 싼 품목만 고른다. 근거가 얇으면 "싸다"고 말하지 않는다.
3. 할인폭 큰 순으로 최대 6개, 가로로 넘겨 보게 한다.

**화면에서 챙길 것**

- "연 최고가보다 N% 싸요" + 근거 라벨("1년 시세 기준").
- 해당 품목이 없는 달에는 섹션 자체를 숨긴다.

**정해야 할 것** 월별 최저가 시기와 통합할지.

### 온라인가 비교

**정의** 컬리·쿠팡·G마켓·B마트 가격을 **판매 방식과 함께** 보여준다. 오프라인 판단의 **보조** 기준이다.

**해결하는 문제** 공공 시세만으론 채널별 가격차를 못 보여주는 문제.

**동작**

1. 채널별 가격을 품목 기준 단위로 환산한다. 환산이 불가능한 상품(묶음·박스만 파는 경우)은 아예 넣지 않는다 — 억지 환산이 정보 없는 것보다 위험하다.
2. 기본은 **최저가 한 줄로 접어둔다.** 오프라인 동네 가격이 이 화면의 주인이다.
3. 펼치면 채널별 가격 + 판매 방식(새벽배송·당일배송·오픈마켓·즉시배송) + 단서(배송비 별도·회원가).

**화면에서 챙길 것**

- **판매 방식을 반드시 함께 표기한다.** 즉시배송은 소량이라 구조적으로 비싸고, 오픈마켓은 배송비가 따로다. 방식을 숨기고 금액만 줄 세우면 "즉시배송이 제일 비싸다"는 당연한 결론만 반복돼 정보량이 0이 된다.
- 지금은 컬리만 실측이고 나머지 3채널은 예시다 → "일부 예시"라고 적는다.
- 맨 아래에 "오프라인 동네 가격이 기준이고 온라인은 참고용"임을 밝힌다.

**정해야 할 것**

- 가격 갱신 주기.
- 실제 연결 방법. 쿠팡은 자동 수집 차단이 강하고, G마켓은 판매자별 편차가 크고, B마트는 앱 전용이다. 채널마다 난이도가 달라 한 번에 처리하기 어렵다.

## 2장 · 동네 가격 모으기

공공 시세는 서울 전체 평균까지만 나온다. **우리 동네 가격은 이웃이 알려주는 수밖에 없다.** 이 서비스의 유일한 차별점이자 가장 어려운 부분이다.

### 이웃 제보가

**정의** 이웃이 올린 실제 목격 가격을 동(행정동) 단위로 모아 보여준다.

**해결하는 문제** 공공 시세가 광역 단위까지만 나와 동네 가격을 알 수 없는 문제.

**동작**

1. 제보 방식 선택(촬영 / 직접 입력)
2. 가게 위치 선택
3. 품목·양·가격 입력. 양의 단위는 품목마다 다르다. 촬영이나 즉석 판단을 거쳐 왔으면 이미 채워져 있다.
4. 구매 여부 선택 — 샀는지, 보기만 했는지.
5. 제출 → 완료 화면 → 동네 제보가 목록에 반영.

**화면에서 챙길 것**

- 목록은 3열이다(제보일 / 오늘 시세와의 차이 / 가격).
- **시세 그래프보다 위에 둔다.** 그래프는 참고 자료고, 동네 제보가가 "지금 살까"의 직접 근거다.
- 가게명을 누르면 그 가게의 전 품목 가격으로 이동한다.
- 제보가 없는 동네는 빈 화면 대신 근처 동네 가격을 보여준다(이 장 마지막 참조).

**정해야 할 것** 허위 제보 신고·제재 기준을 둘지. 지금은 이상치를 표시하는 선까지만 한다.

### 촬영 제보

**정의** 사진을 찍으면 품목·양·가격을 미리 채워 제보를 짧게 끝낸다.

**해결하는 문제** 허위·장난 제보를 못 거르는 문제. 사진이 있으면 신뢰도가 올라간다.

**동작** 카메라 열기 → 셔터로 화면 고정 → 인식 결과 확인 → 구매 여부 → 제출.

**화면에서 챙길 것**

- 라이브 / 인식 중 / 오류(권한 거부) 3가지 상태가 다 필요하다.
- 카메라 권한을 거부하면 직접 입력으로 유도한다.
- 촬영 진입은 제보 방식 선택(F03-1) 한 곳뿐이다.

**정해야 할 것** 실제 이미지 인식을 언제부터 붙일지. 지금은 항상 감자로 인식되는 예시 동작이다.

### 가게 위치 특정

**정의** 현재 위치로 근처 청과물·마트를 찾아, 제보 위치를 동보다 좁게 특정한다.

**해결하는 문제** 동 단위로 받아도 "어느 가게"인지는 모른다는 문제.

**동작** 위치 확인 → 근처 가게 검색(청과·채소·과일이 들어간 상호) → 목록에서 선택. 목록에 없으면 직접 입력.

**화면에서 챙길 것** 검색 결과가 없으면 바로 직접 입력 폼으로 전환한다. 빈 목록을 보여주고 끝내지 않는다.

**정해야 할 것** 검색 반경. 지도 서비스 실제 연결 시점.

### 제보 신뢰 표시

**정의** 제보마다 신뢰 신호 3가지를 붙여 "이거 믿을 수 있나"에 답한다.

**해결하는 문제** 이웃 제보가가 유일한 차별점인데 검증 장치가 없었다. **틀린 제보 하나가 서비스 전체 신뢰를 깎는다.**

**동작**

1. **얼마나 최신인가** — 오늘 / 어제 / N일 전. 1주일이 넘으면 흐리게 처리하고 "오래된 가격"임을 알린다. 야채 가격은 주 단위로 움직여서, 낡은 제보를 새 제보와 같은 무게로 보여주면 오히려 잘못된 판단을 부른다.
2. **몇 명이 확인했나** — 같은 가게·같은 품목에 제보가 2건 이상이면 "이웃 N명 확인"을 붙인다. 1건은 근거가 얇고, 2건부터는 서로가 증인이 된다.
3. **말이 되는 값인가** — 시세의 3배가 넘거나 3분의 1보다 싸면 오타·장난일 확률이 높다. **지우지 않고** 목록 맨 아래로 내리고 "확인 필요"로 표시한 뒤, 평균 계산에서만 뺀다.

**화면에서 챙길 것** 시세 화면 제보 목록과 가게 상세에 같은 규칙을 적용한다.

**정해야 할 것** 이상치 기준(3배 / 3분의 1)과 오래됨 기준(7일)이 적절한지. 품목별로 달라야 하는지.

### 구매 장소 공개

**정의** 제보 목록에 다녀온 가게명을 노출하고, 누르면 그 가게 화면으로 보낸다.

**해결하는 문제** 가격만 보면 "그래서 어디로 가야 하나"를 모른다는 문제. 가게 단위로 보는 입구가 된다.

**동작** 제보 시 고른 가게를 저장 → 목록에 가게명 표시 → 누르면 가게 상세.

**화면에서 챙길 것** 가게를 안 고른 제보는 가게명 줄을 생략한다.

**정해야 할 것** 가게 사장님이 반발할 경우 비공개 옵션을 둘지.

### 근처 동네 가격

**정의** 우리 동네 제보가 없으면 **가까운 동네 3곳**의 가격을 출처와 함께 보여준다.

**해결하는 문제** 제보 없는 동네는 화면이 거의 다 비어 있다. 이웃 제보 기반 서비스의 첫 사용자는 **반드시** 이 상태를 만나고, 빈 화면만 보면 "쓸 데이터가 없는 앱"으로 판단하고 떠난다.

**동작** 우리 동네 제보가 0건인지 확인 → 거리순으로 가까운 동네를 훑어 제보가 있는 곳 3곳 → 동네명·최신 가격·시세와의 차이·최신 여부를 함께 노출.

**화면에서 챙길 것** "대신 근처 동네 가격을 참고하세요"라고 명시해 우리 동네 값이 아님을 밝힌다. 정확도는 낮지만 어느 동네 값인지 밝히면 오해가 없고, 아무것도 없는 것보다 낫다.

**정해야 할 것** 거리 상한. 근처 동네 값을 판정 기준으로도 쓸지(지금은 표시만 한다).

## 3장 · 판단 돕기

가격을 모아놓는 것과 **"그래서 살까?"에 답하는 것**은 다르다. 이 장은 후자다.

### 즉석 판단(신호등) — F10

**정의** 품목·단위·가격만 넣으면 우리 동네 기준으로 **🟢 사도 좋음 / 🟡 적당함 / 🔴 비쌈**을 한 화면으로 알려준다.

**해결하는 문제** 매장 가격표 앞에서 앱을 켜는데, 홈 → 검색 → 품목 → 시세 화면을 여러 번 스크롤해야 판단이 됐다. **판단까지 너무 멀다.**

**동작**

1. 홈 최상단 또는 시세 화면에서 진입
2. 품목 선택 — 찜한 야채와 자주 찾는 야채가 먼저 뜨고, 검색도 된다
3. 파는 단위 선택(1kg·1단·1망·1박스 등) — 환산은 앱이 한다
4. 가격 입력 → **입력하는 동안 바로 판정**
5. 판정 후 "이 가격 제보하기" → 넣은 값이 그대로 제보로 넘어간다

**판정 기준** 우리 동네 최저 제보가가 있으면 **그것**을 기준으로, 없으면 오늘 공공 시세를 기준으로 쓴다. "같은 동네에서 이 가격에 산 사람이 있다"가 더 강한 근거다. 기준보다 8% 이상 싸면 초록, 8% 이상 비싸면 빨강, 그 사이는 노랑.

**화면에서 챙길 것**

- 판정 카드는 **결론 → 근거 → 다음 행동** 순서로 읽히게 한다. 무엇과 비교했는지(기준 가격, 제보 몇 건)를 반드시 밝힌다.
- 색만으로 뜻을 전하지 않는다. 문구가 결론을 그대로 말한다.
- 시세 데이터가 없는 품목은 판정하지 않고, 대신 제보를 권한다.
- 하단 버튼은 **항상 자리를 지킨다**(비활성 상태로). 판정될 때 버튼이 새로 나타나면 입력 중에 화면이 위로 튄다.

**정해야 할 것** 8% 기준이 적절한지. 품목별로 다르게 둘지.

### 시장 단위 환산

**정의** 시장에서 실제로 파는 단위(1단·1망·1박스·묶음)를 비교 가능한 기준 단위로 환산한다.

**해결하는 문제** 46종의 기준 단위가 kg·g·개·포기로 갈리고, **시장은 kg로 안 파는 경우가 많다.** 환산이 없으면 비교 자체가 불가능하다.

**동작**

1. 품목 단위에 맞는 후보를 제시한다(kg 품목이면 1kg·1단·1망·1박스, 개 품목이면 1개·3개 묶음·1봉지 등).
2. 사용자가 파는 단위를 고르고 그 단위의 가격을 넣는다.
3. 앱이 기준 단위로 환산하고 **근거를 문구로 밝힌다** — "1망은 1.5kg으로 계산했어요".

**화면에서 챙길 것** 즉석 판단과 제보 폼에 단위 선택이 있어야 한다. 장바구니 수량 표기도 품목 단위를 따른다(오이는 "3개", 배추는 "1포기").

**정해야 할 것** 1단·1망의 환산 계수. 지금은 단 0.8kg / 망 1.5kg으로 가정했는데 **지역·품목마다 달라 실측이 필요하다.** 이 값이 틀리면 판정 전체가 틀린다.

### 가게 상세 — F09

**정의** 한 가게의 전 품목 가격을 한 화면에 모아 "이 가게는 뭐가 싸고 뭐가 비싼가"에 답한다.

**해결하는 문제** 모든 화면이 품목 단위라 **"오늘 어느 가게 갈까"에 답하는 화면이 없었다.** 서비스가 풀려는 문제(가게 비교)에 정면으로 답하는 화면이다.

**동작**

1. 싼 가게 순위 / 제보 목록의 가게명 / 홈 단골집 카드에서 진입
2. 제보를 가게별로 묶고, 같은 품목은 **가장 최근 것**을 대표로 쓴다(가격은 시간에 민감하다)
3. **시세보다 싼 품목 순**으로 정렬 — 이 가게에 갈 이유가 먼저 읽혀야 한다
4. 우측 상단에서 단골로 등록할 수 있다

**화면에서 챙길 것**

- 요약 한 줄: "제보 N개 품목 · M개가 시세보다 싸요 · 최근 제보 O일 전"
- 품목마다 최신 여부·확인한 이웃 수·이상치 표시
- 제보가 없는 가게는 빈 상태 + 제보 유도
- **뒤로 가면 온 길로 돌아간다.** 여러 경로에서 들어오는 화면이라 목적지를 하나로 고정하면 엉뚱한 곳으로 나간다.

**정해야 할 것** 가게 단위 비공개 옵션(구매 장소 공개와 같은 이슈).

### 싼 가게 순위

**정의** 우리 동네 가게를 시세 대비 평균이 싼 순으로 줄 세운다.

**해결하는 문제** 품목별 최저가만 알려주면 가게가 흩어진다는 문제.

**동작** 시세 대비 평균이 싼 순 → 같으면 제보가 많은 순(근거가 두꺼운 쪽).

**화면에서 챙길 것**

- 이 순위는 **실제 제보 집계**다. 같은 화면의 다른 두 순위(최저가 품목·제보왕)는 예시라 구분이 필요하다.
- 가게별 제보가 없으면 빈 상태 + "제보할 때 가게를 골라주시면 순위가 생겨요".

**정해야 할 것** 실서비스에서 집계 주기(실시간 / 하루 1회).

## 4장 · 장보기 실행

계획을 세우고 실제로 장을 보고 돌아오는 흐름 전체를 앱 안에서 이어준다. **제보가 이 흐름의 부산물로 나오게 만드는 것**이 핵심이다.

### 장바구니 — F07

**정의** 살 품목과 수량을 담아 예상 총액을 비교한다. 실제 결제는 없고 **계획 도구**다.

**해결하는 문제** 품목을 하나씩만 보면 "오늘 장보기 전체 예산"을 가늠할 수 없다.

**동작**

1. 시세 화면이나 장바구니 안에서 담는다(찜한 야채 빠른 담기, 지난 장보기 복원도 여기).
2. 수량 조절·삭제. 단위는 품목을 따른다.
3. **두 가지 총액을 구분해서** 보여준다 — 공공 시세 기준, 그리고 동네 최저가를 전부 모았을 때.
4. 다음 단계로 두 갈래를 준다: 내가 직접 간다(매장 모드) / 가족에게 부탁한다(심부름 목록).

**화면에서 챙길 것**

- 동네 최저가 합계는 **가게가 흩어져 한 번에 살 수 없는 이론값**이다. "가게가 흩어져 있을 수 있어요"를 반드시 붙이고, 실현 가능한 안은 장보기 코스가 담당한다.
- 빈 상태에 찜한 야채 빠른 담기와 지난 장보기 복원을 함께 둔다.
- 삭제 경로는 하나만 둔다.

**정해야 할 것** 구매 확정(결제) 단계를 붙일지, 계획 전용으로 남길지.

### 장보기 코스

**정의** 담은 목록을 기준으로 "한 곳에서 다 사기"와 "두 곳 돌기"의 금액을 비교해준다.

**해결하는 문제** 최저가를 따라가면 가게가 흩어져 발걸음이 늘어난다. **비용 절약이 노력 절약을 잡아먹는다.**

**동작**

1. 가게별·품목별 최신 가격을 모은다(이상치 제외).
2. 한 곳 안은 **담은 품목을 많이 커버하는 가게** 우선, 같으면 총액이 싼 쪽.
3. 두 곳 조합을 모두 계산해 가장 싼 조합을 찾는다.
4. **두 곳이 실제로 더 싸지 않으면 제안하지 않는다.** 괜히 발걸음만 늘린다.
5. 제보가 없는 품목은 공공 시세로 채우고, 몇 개가 그랬는지 밝힌다.

**화면에서 챙길 것**

- 한 곳 안에 "추천" 표시.
- 두 곳 안은 트레이드오프를 한 문장으로: "한 곳보다 1,600원 더 아끼지만 가게를 한 곳 더 들러야 해요".
- 가게별 제보가 없으면 코스 대신 제보를 권한다.

**정해야 할 것** 실제 이동 거리·시간을 계산해 넣을지. 지금은 "가게 수"로만 노력을 표현한다.

### 장보는 중(매장 모드) — F11

**정의** 담은 목록을 하나씩 넘기며 가격을 확인하고, 마지막에 **산 것을 한 번에 제보**한다.

**해결하는 문제** 계획은 있는데 **매장에서 쓰는 화면**이 없었다. 5품목을 확인하려면 품목마다 화면을 오가야 했고, 다 사고 나서 제보를 또 따로 해야 했다.

**동작**

1. 장바구니에서 "장보기 시작하기"
2. 품목마다 가격을 넣으면 바로 판정 → "담았어요" 또는 "안 살래요"
3. 다음 야채로 넘어간다(몇 개 남았는지 표시)
4. **마지막 품목에서만** 가게를 묻는다. 품목마다 물으면 5번 반복이다.
5. "장보기 끝내고 제보하기" → 산 것과 안 산 것을 모두 제보로 남긴다(안 산 것도 목격한 가격이라 동네 시세에 기여한다) → 장바구니를 비운다
6. 완료 화면에서 담은 개수·지출과 "이웃에게 도움이 됐다"를 알린다

**화면에서 챙길 것**

- **뒤로 가면 이전 품목으로** 돌아간다. 화면을 나가버리면 매장에서 입력한 가격이 전부 사라진다. 첫 품목에서만 화면을 벗어난다.
- 진행 상황을 항상 보이게 한다. 매장에서 가장 궁금한 것이 "몇 개 남았나"다.
- 장바구니가 비어 있으면 시작할 수 없다 → 장바구니로 유도.
- 시세가 없는 품목은 판정을 건너뛰되 가격은 받는다.

**정해야 할 것**

- 두 가게에서 나눠 산 경우 가게명이 하나로 뭉친다. 지금은 문구로 밝히는 선까지만 했다. 품목별 가게 입력을 둘지.
- 끝낸 뒤 되돌리기(제보 취소) 경로를 둘지.

### 심부름 목록 — F12

**정의** 담은 목록을 링크로 넘기면, 받은 사람은 **살 목록과 "이 가격까지는 사도 된다"는 상한**만 본다.

**해결하는 문제** 타깃이 4인 이상 가족의 장보기 담당인데 **앱이 완전히 1인용이었다.** 장보기를 부탁받은 사람(배우자·자녀)은 시세를 몰라 비싸게 사 온다.

**동작**

1. 장바구니에서 "가족에게 장보기 부탁하기"
2. 기본 공유 → 안 되면 링크 복사 → 둘 다 막히면 링크를 화면에 그대로 보여준다
3. 받은 사람은 체크리스트로 담으며 진행 상황을 확인한다

**화면에서 챙길 것**

- 상한은 **담을 수량 전체 기준**으로 준다. 매장에서 단가를 곱하게 만들면 안 된다.
- 상한이 **어느 동네 기준**인지 밝힌다. 받은 사람의 위치가 보낸 사람과 다를 수 있다.
- 기준 가격이 없으면 상한도 만들지 않는다 — "보내주신 분께 물어보세요".
- **시세 그래프·제보 목록은 넣지 않는다.** 이 사람은 판단을 배우러 온 게 아니라 심부름 중이다.
- 하단에 즉석 판단 진입을 둔다. 심부름하는 사람이 이 서비스를 처음 쓰게 되는 지점이다.

**정해야 할 것** 링크 유효기간. 심부름 결과를 보낸 사람에게 알릴지(지금은 단방향).

### 지난 장보기 복원

**정의** 내 구매 이력을 **날짜(= 한 번의 장보기) 단위**로 묶어 장바구니에 그대로 되살린다.

**해결하는 문제** 같은 품목을 주기적으로 다시 사는데 매번 새로 담게 하는 건 시간·노력 낭비다.

**동작** 구매 이력을 날짜별로 묶어(사용자의 기억 단위가 "그날 장 본 것") 최근 2회를 품목 목록과 그날 총액과 함께 보여주고, 버튼 하나로 전부 되살린다.

**화면에서 챙길 것** 장바구니 빈 상태에 노출한다. 구매 이력이 없으면 숨긴다.

**정해야 할 것** 몇 회분까지 보여줄지. 그날 가격도 함께 보여줄지.

## 5장 · 다시 오게 하기

한 번 쓰고 끝나지 않게 만드는 장치들이다. **"눈으로 보는 변화"**를 보여주는 것과 **"지금 열어볼 이유"**를 만드는 것 두 갈래다.

### 소비 요약·절약 계산

**정의** 산 것만 모아 그날 시세와 비교해 절약·초과 금액을 계산한다.

**해결하는 문제** 사고 나서 잘 산 건지 모른다는 문제. 제보할 이유도 여기서 생긴다.

**동작** 구매 표시된 제보 → 그날 시세와 비교 → 절약·초과 계산 → 마이페이지 상단에 고정.

**화면에서 챙길 것** 구매가 없으면 "야채를 사고 가격을 제보하면 시세보다 얼마나 아꼈는지 알려드려요". 절약은 초록, 초과는 주황.

**정해야 할 것** 초과했을 때 문구 톤(비난처럼 읽히지 않게).

### 주간 리포트

**정의** 최근 7일 구매만 모아 "이번 주에 얼마 아꼈나"와 "가장 잘 산 품목"을 보여준다.

**해결하는 문제** 누적 요약은 첫 달이 지나면 숫자가 커져서 **변화가 안 느껴진다.** 장보기는 주 단위 리듬이라 주간이 사용자가 체감하는 단위다.

**동작** 최근 7일 구매 집계 → 절약 합계 → 절약액이 가장 큰 품목을 "가장 잘 산 것"으로 지목.

**화면에서 챙길 것** 칭찬 대상이 구체적이어야 다음 행동으로 이어진다 → 품목명 + 금액 + 가게명을 같이 말한다. 이번 주 구매가 없으면 숨긴다.

**정해야 할 것** 주 시작을 월요일로 고정할지, 최근 7일로 둘지(지금은 최근 7일).

### 재구매 주기

**정의** 내 구매 간격에서 다시 살 시점을 추정해 "그거 살 때 됐어요"를 홈에서 알려준다.

**해결하는 문제** 매번 시세를 확인하러 앱을 켜야 하는 문제.

**동작** 품목별 구매 간격의 평균을 주기로 쓴다. 이력이 1건뿐이면 근거가 없어 14일을 기본으로 쓰고, **가정임을 문구로 밝힌다.** 주기를 넘긴 품목만 많이 지난 순으로 최대 4개.

**화면에서 챙길 것** "마지막 구매 N일 전 · 보통 M일마다 사셨어요". 해당 품목이 없으면 숨긴다.

**정해야 할 것** 가격 알림 설정과 통합할지. 둘 다 "다시 살 때를 알려준다"는 같은 목적이다.

### 가격 알림 설정

**정의** 찜한 야채마다 가격 알림을 켜고 끈다. **지금은 화면만 있고 실제 발송은 없다.**

**해결하는 문제** 매번 시세를 확인하러 앱을 켜야 하는 문제.

**동작** 마이페이지에서 찜한 야채별로 토글.

**화면에서 챙길 것** 찜한 야채가 없으면 안내 문구. **예시 기능임을 라벨로 명시한다.**

**정해야 할 것** 실제 발송 인프라 도입 시점. 알림 기준(며칠 내 몇 % 하락).

### 뱃지

**정의** 제보·구매 건수가 기준을 넘으면 단계별 뱃지를 준다.

**해결하는 문제** 제보할 유인이 없다는 문제.

**동작** 내 제보·구매 건수 집계 → 기준(제보 1·5·15건, 구매 3건) 통과 여부.

**화면에서 챙길 것** 아직 못 받은 뱃지도 흐리게 보여줘 다음 목표를 알린다.

**정해야 할 것** 종류와 기준을 실사용 데이터로 재조정할지.

### 단골 가게

**정의** 자주 가는 가게를 등록해두고 홈에서 "단골집 오늘 가격"을 먼저 본다.

**해결하는 문제** 반복 구매가 타깃의 특성인데 매번 가게를 다시 찾는 건 낭비다.

**동작** 가게 화면에서 등록·해제 → 홈에 요약 카드(품목 수, 최근 제보 시점, 시세 대비 평균).

**화면에서 챙길 것** 단골이 없으면 **아무것도 그리지 않는다.** 빈 카드로 홈을 늘리지 않는다.

**정해야 할 것** 개수 상한. 단골 가게 가격이 바뀌면 알릴지.

### 최저가 품목 순위 · 제보왕 순위

**정의** 동네에서 오늘 가장 싼 품목 순위와, 이번 주 제보를 많이 한 사람 순위. **둘 다 예시 데이터다.**

**해결하는 문제** 시세 화면만 봐서는 계속 켜볼 이유가 약하다는 문제.

**화면에서 챙길 것** "예시 데이터입니다 · OO동 기준"을 반드시 표시한다. 같은 화면의 싼 가게 순위는 실데이터라 구분이 필요하다.

**정해야 할 것** 실서비스 집계 주기.

### 카드뉴스

**정의** "요즘 이 야채 싸요 / 비싸요"를 홈에서 먼저 알려주는 콘텐츠. **예시 데이터다.**

**해결하는 문제** 그래프는 눌러봐야 보인다는 문제. 가만히 있어도 정보가 오게 한다.

**화면에서 챙길 것** 전부 예시임을 라벨로 명시.

**정해야 할 것** 콘텐츠를 사람이 쓸지, 시세 계산으로 자동 생성할지.

### 레시피 연계

**정의** 품목별 간단 레시피를 시세 화면에서 보여준다. **예시 데이터다.**

**해결하는 문제** 가격만 알려주면 "그래서 뭘 해먹지"가 안 풀린다.

**화면에서 챙길 것** **기본으로 접어둔다** — "지금 살까" 판단에 필요한 정보가 아니다. "예시 · 제휴 아님" 라벨. 레시피가 없는 품목은 섹션 자체를 숨긴다.

**정해야 할 것** 실제 레시피 제휴 여부.

### 동네 댓글

**정의** 시세 화면 아래에서 같은 동 이웃끼리 한마디를 남긴다.

**해결하는 문제** 제보가 일방향 데이터라 이웃 간 소통·신뢰가 안 쌓인다는 문제.

**동작** 같은 동·같은 품목 댓글만 보이고, 닉네임과 내용을 남긴다.

**화면에서 챙길 것** **기본으로 접어둔다**(판단 근거를 밀어내지 않게). 댓글이 없으면 "아직 댓글이 없어요". 한글 입력 중 엔터로 미완성 글이 올라가지 않게 한다.

**정해야 할 것** 실제로 산 사람만 댓글을 달게 할지.

## 6장 · 찾기·시작하기

46종 중에서 원하는 것을 빨리 찾고, 처음 온 사람이 자기 동네를 정하는 부분이다.

### 야채 검색 (초성 포함)

**정의** 이름 또는 초성으로 46종을 찾는다. "ㄱㅈ"로 감자가 나온다.

**해결하는 문제** 9종일 때는 눈으로 찾았지만 46종에서는 **이름을 정확히 입력하는 것이 병목**이다. "고춧가루(국산)"처럼 긴 이름은 사실상 검색으로 못 찾는다.

**동작** 입력이 초성만이면 초성으로 찾고, 아니면 이름 일부로 찾는다. 초성 입력에 이름 검색까지 함께 걸면 "ㄱ" 하나에 온갖 게 걸려 결과가 무의미해진다.

**화면에서 챙길 것** 입력창 안내 문구에 예시를 넣는다("예: ㄱㅈ"). 결과가 없으면 빈 상태.

**정해야 할 것** 이름이 비슷한 품목(대파/쪽파, 적상추/청상추, 애호박/쥬키니)을 결과에서 어떻게 구분해 보여줄지.

### 종류별 필터

**정의** 46종을 7가지로 걸러 본다 — 감자·뿌리 / 잎채소 / 열매채소 / 고추 / 양념 / 버섯 / 과채.

**해결하는 문제** 46종을 3열로 늘어놓으면 16줄이라 홈이 스크롤에 잠긴다.

**동작** 종류를 고르면 그 종류만 보인다. **검색어가 있으면 종류 필터를 무시한다** — 이름을 아는 사람은 이미 목적지가 있고, 두 필터가 동시에 걸리면 결과가 왜 비었는지 알 수 없다.

**화면에서 챙길 것** 검색 중에는 종류 칩을 숨긴다.

**정해야 할 것** 분류 기준이 실제 장보기 감각과 맞는지. 지금은 "장 볼 때 묶는 방식"으로 임의 분류했다.

### 찜하기

**정의** 관심 품목을 저장해 홈·마이페이지에서 빨리 찾는다.

**해결하는 문제** 자주 사는 몇 개를 매번 찾아야 하는 문제.

**동작** 그리드나 시세 화면에서 하트로 토글. 찜한 야채는 즉석 판단 품목 선택에서도 먼저 나온다.

**화면에서 챙길 것** 찜한 게 없으면 빈 상태 문구.

### 홈 시세·등락 표시

**정의** 홈 목록 각 칸에 오늘 시세와 어제 대비 등락을 함께 보여준다.

**해결하는 문제** 홈이 야채 그림만 있어서 **어느 야채를 볼지 정할 정보가 없었다.** 하나씩 들어가 봐야 했다.

**동작** 어제와 오늘을 비교한다. **0.5% 미만 변화는 "어제와 같음"으로 본다** — 매일 ±10원에 화살표가 뒤집히면 신호가 아니라 잡음이다.

**화면에서 챙길 것** 오르면 빨강, 내리면 초록(사는 사람 기준). 화살표만으로 뜻을 전하지 않는다.

**정해야 할 것** 등락 기준을 어제로 둘지 주간 평균으로 둘지.

### 온보딩 (닉네임 + 동네)

**정의** 첫 진입에 닉네임과 동네(행정동)를 받아 이후 이웃으로 표시한다.

**해결하는 문제** 제보에 소속감과 권위를 부여한다. 동네가 정해져야 나머지 기능이 동작한다.

**동작** 닉네임 입력 → 위치로 동네 자동 감지 → 필요하면 수동 보정 → 완료 → 홈.

**화면에서 챙길 것** 위치 권한을 거부하면 수동 선택 화면이 필요하다. **동 단위로 고른다** — 구 단위는 "우리 동네" 체감이 안 난다.

**정해야 할 것** 닉네임을 필수로 할지.

### 첫 제보 안내

**정의** 제보를 한 번도 안 한 사람에게만 홈에서 첫 제보를 권한다.

**해결하는 문제** 온보딩까지 마쳐도 "왜 내가 제보해야 하나"에 답이 없으면 보기만 하고 끝난다.

**동작** 내 제보가 0건이면 안내 카드를 띄운다. **우리 동네 제보 건수를 함께** 보여줘 "여기 사람들이 이미 쓰고 있다" 또는 "아직 내가 첫 번째다" 중 하나로 동기를 만든다.

**화면에서 챙길 것** 제보를 한 번이라도 한 사람에게는 숨긴다. 남아 있으면 잔소리가 된다.

## 개발 전제

여기부터는 **구현·백엔드 협의용**이다. 기획·디자인 의사결정에는 필요하지 않다.

**비교 기준(시세)은 항상 서버에서 내려준다.**
제보는 기기에 저장돼 있어 목록은 화면에서 만들지만, 비교 기준까지 화면에서 임시값으로 계산하면 실제 시세 API를 붙일 때 숫자가 어긋난다. 품목→시세 대응표를 서버에서 한 번 만들어 순위·장바구니·가게 상세·즉석 판단·매장 모드가 같은 값을 쓴다.

**기준일(오늘)도 서버에서 내려준다.** 제보 최신 여부·주간 리포트가 기기 시계에 흔들리지 않게 한다.

**이웃 제보 예시 데이터는 동네별로 필요할 때 만든다.** 46종 × 100여 개 동을 미리 만들면 1만 건이 넘어 화면을 그릴 때마다 정렬 비용이 커진다.

**홈은 46종 기준값을 서버에서 한 번에 모아 요약만 화면으로 보낸다.** 기간별 값 전체(약 2,200개 점)를 보내면 전송량이 과하다.

**시세 캐싱** 하루 1회 갱신되는 데이터라 1시간 단위로 재검증한다. 홈·순위·장바구니 화면도 같은 주기.

**인증키는 서버에만 둔다.** 시세 API 키가 화면 코드에 들어가지 않도록 서버 전용 모듈로 격리했다.

## 정해야 할 것 (우선순위)

데이터 정확성이 걸린 1~3번이 먼저다. **틀리면 화면이 조용히 잘못된 값을 보여준다.**

1. **46종 등급 코드 최종 검증** — 틀리면 해당 품목이 빈 값으로 나온다
2. **배추·무 계절 품종 코드 4개 실제 값** — 규격 문서에 없다
3. **1단·1망 환산 계수 실측** — 틀리면 판정 전체가 틀린다
4. 방울토마토 단위가 "개"인지 팩인지
5. 판정 기준 8%, 이상치 3배 / 3분의 1, 오래됨 7일 — 실사용 후 재조정
6. 온라인 3채널(쿠팡·G마켓·B마트) 실제 연결 방법과 갱신 주기
7. 허위 제보 신고·제재 기준 / 가게 비공개 옵션
8. 가격 알림 실제 발송 인프라
9. 매장 모드에서 두 가게에 나눠 산 경우 처리
10. 심부름 링크 유효기간·결과 회신

### UT 전에 먼저 정할 것 2가지

**① 예시 데이터를 어디까지 보여줄까**
지금 "예시"인 곳은 최저가 품목 순위 · 제보왕 순위 · 카드뉴스 · 레시피 · 가격 알림 · 온라인 3채널이다. 참가자가 "미완성 앱"으로 인식하면 정작 검증하려는 **이웃 제보가**에 대한 반응이 흐려진다.

**② 제보 경로를 하나로 정할까**
매장 모드(F11)가 기존 제보 흐름(제보 방식 선택 → 가게 선택 → 폼 → 완료, 4화면)을 사실상 대체한다. 장바구니를 쓰는 사람에겐 매장 모드가 항상 더 빠르다. 두 경로를 다 열어두면 참가자가 어느 쪽을 쓸지 갈려 **결과 해석이 어려워진다.**
