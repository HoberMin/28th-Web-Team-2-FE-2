메인기능 — 기능 단위 정리, 2026-07-30 갱신(볼륨 확장 → 기능 다이어팅 반영)

메인 기능을 최상위로 두고, 부가기능은 리스크 해결장치로 그 아래 배치. 2depth(리스크→해결장치)까지만 기록, 그 밑은 세부기능 정의 때 채움. 리스크는 기획 리스크만. 중요도 높은 순.

세부기능 단위 정의는 → `detail-features.md` / 46종 데이터 규격은 → `kamis-vegetable-data-spec.md`

#### 공공 시세 조회(KAMIS)

필요한 이유: 판단 기준선이 없다. 공신력 있는 숫자를 기준으로 삼는다.

리스크
- 품목·품종·등급 선택이 틀리면 기준 자체가 틀린다
  - 해결 장치(2026-07-29 해소): 데이터 규격 v3 — 46종 품목·품종·등급·단위를 실측으로 확정. 등급은 상품 고정, 배추·무는 계절형 조회
- 시·도 기준이라 채널별(마트·온라인) 가격차를 못 보여준다
  - 해결 장치: 온라인가 비교 — 컬리·쿠팡 등 크롤링

#### 이웃 제보가

필요한 이유: 공공 시세는 시·도 단위까지만 나온다. 이웃 제보로 동네 단위 공백을 메운다. 서비스의 유일한 차별점.

리스크
- 제보할 유인이 없다(귀찮음)
  - 해결 장치: 소비 요약·절약 계산
  - 해결 장치: 온보딩(닉네임+동네) — 소속감과 권위 부여
  - 해결 장치: 뱃지 — 제보·구매 인증 건수로 단계별 보상
- 허위·장난 제보를 못 거른다
  - 해결 장치: 촬영 제보
- 구 단위도 넓어 문제가 안 풀릴 수 있다
  - 해결 장치: 정확한 위치 찍기(GPS + Kakao 검색)
  - 해결 장치: 동네 단위를 구(자치구)에서 동(행정동)으로 세분화(2026-07-30) — "봉천구" 아니라 "봉천동" 체감
- 가게 위치가 찍히면 가게 사장님이 반발할 수 있다
- 제보 목록만 봐서는 "같은 동 사람들"이라는 신뢰·소통이 안 생긴다
  - 해결 장치: 구매 장소 공개 — 제보 목록에 가게명 노출(핵심가치 ④ 관계·동반)
  - 해결 장치: 동네 댓글 — 제보에 이웃이 댓글로 반응
- 제보가 가게마다 1~2건씩 흩뿌려지면 "이 가게가 전반적으로 싼가"에 답할 수 없다(가게 축의 전제가 무너진다)
  - 해결 장치: 제보 완료 화면의 연속 입력 — 가게명은 유지하고 품목만 교체

#### 시세 그래프(기간 전환)

필요한 이유: 판단 근거가 기억뿐이다. 과거 추이로 보완한다.

리스크
- 데이터가 부족한(KAMIS에서 미제공) 품목은 그래프가 빈 구간이 존재할 수 있다. 

#### 찜하기 + 야채 검색

필요한 이유: 46종 중 자주 사는 것만 빠르게 다시 찾는다.

리스크
- 이름 비슷한 품목(대파/쪽파 등)이 많아 검색해도 헷갈릴 수 있다

#### 가게 비교

필요한 이유: 앞의 기능이 전부 품목 축이라 "오늘 어느 가게 갈까"에 답하는 자리가 없다. 품목별 최저가만 주면 가게가 흩어져 발걸음이 늘고, 비용 절약이 노력 절약을 상쇄한다.

리스크
- 가게마다 제보된 품목 구성이 달라 단순 평균으로 줄 세우면 가게가 아니라 품목 구성을 비교하게 된다
  - 해결 장치: 순위 기준을 시세 대비 편차 평균으로. 품목 구성이 달라도 비교 성립
- 첫 사용자는 단골이 없어 탭이 빈 화면이 된다
  - 해결 장치: 상단 단골 / 하단 동네 가게 2층 구성. 단골 0개여도 하단이 화면을 채움
- 싼 곳만 보여주면 먼 가게로 유도된다
  - 해결 장치: 거리·도보 시간 병기. 선택은 사용자 몫
- 알림이 와도 "그래서 어디로 가지"가 남으면 행동으로 안 이어진다
  - 해결 장치: 알림 — 단골 가게에 더 싼 제보가 올라오면 하루 1회 다이제스트에 포함. 목적지가 이미 붙어 있다

## 부가 기능 (볼륨 확장 → 다이어팅, 2026-07-30)

"기능이 4개뿐이라 볼륨이 적다"에서 나온 아이데이션을 붙였다가, 같은 날 "해결하는 문제가 작다"를 기준으로 다시 걷어냈다. 전부 "어떤 빈틈을 채우는지"가 명확해야 남긴다.

유지

- **GNB(홈/야채시세/랭킹/가게/마이페이지)** — 채우는 빈틈: 화면이 늘면서 진입 동선이 필요해짐. 3번째 자리는 장바구니에서 가게로 교체(2026-07-30). 2026-07-31 홈 개편으로 **야채시세** 탭 신설 — 홈이 대시보드로 바뀌며 46종 전체 조회가 전용 탭으로 분리됐다.
- **랭킹(F06)** — 채우는 빈틈: 시세 화면만으로는 "계속 켜볼 이유"가 약하다. 제보왕 단독으로 재편(2026-07-31 — 싼 가게는 가게 탭으로, 최저가 품목은 홈 「오늘 최저가」로 이동).
- **카드뉴스(F08)** — 채우는 빈틈: 그래프는 능동적으로 눌러야 보인다. 홈에서 수동적으로 알려줌.
- **알림(마이페이지)** — 채우는 빈틈: 매번 시세를 확인하러 앱을 켜야 한다. 품목별·가게별 개별 토글에서 전역 토글 하나 + 하루 1회 다이제스트(찜한 야채 + 단골 가게)로 통합(2026-07-31, `detail-features.md` 「알림」).
- **월별 최저가 시기(F03)** — 채우는 빈틈: "언제 사는 게 싼지" 근거가 없다. 실시세 12개월 평균에서 계산.

배제 (2026-07-30)

- **장바구니(F07)** — 담아둔 목록이라는 점에서 찜하기와 구별되지 않았다. 실제 역할은 가게 모드·심부름의 입력 폼이었고, 총액 예산이라는 사용자 고민 자체가 얇다.
- **가게 모드(F11)** — 장바구니가 사라지면 입력이 없다. 반복 입력 절감이라는 가치는 잃지만, 제보 공급은 제보 완료의 연속 입력이 대신한다.
- **심부름 목록(F12)** — 사용자 문제는 가장 선명했으나 장바구니 없이는 성립하지 않는다. 재도입 여지 있음.
- **장보기 코스 / 지난 장보기 복원** — 위 화면들에 딸린 기능.
- **레시피 연계** — "그래서 뭘 해먹지"는 이 서비스가 풀려는 문제가 아니다. 구매 판단에 기여하지 않아 시세 화면에서 제거.
