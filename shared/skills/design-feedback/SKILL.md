# 디자인 피드백 문서 규격

목적: 코드를 Figma에 맞춘 뒤 남는 "디자이너 확인이 필요한 항목"을, 디자인팀이 하나씩 보고 체크할 수 있는 형태로 넘긴다.

## 어디에 쓰는 규격인가 (auditor와 구분)

| | design-feedback (이 문서) | figma-handoff-auditor §출력 형식 |
|---|---|---|
| 대상 | 코드 ↔ Figma 비교 | Figma 파일 자체 |
| 언제 | 토큰 sync·컴포넌트 구현 후 | 핸드오프 전 파일 정리 |
| 저장 | 디자인_docs/feedback/ | 디자인_docs/audit/ |
| 작성자 | 구현 agent 또는 메인 세션 | figma-handoff-auditor |

두 규격은 별개다. 서로의 섹션 구성을 가져다 쓰지 않는다.

## 표기 규칙 (고정)

- 볼드 금지. 강조하고 싶으면 항목 순서를 위로 올린다.
- 백틱·코드블록·인용문 금지. 토큰명·컴포넌트명은 그냥 평문으로 쓴다 (content/rank/king).
- 이모지 금지. 체크박스만 쓴다.
- 링크는 허용 — Figma 노드·이전 문서로 바로 갈 수 있어야 한다.
- 항목은 GitHub 체크박스 목록으로 쓴다. 표를 쓰지 않는 이유는 표 안의 체크박스가 GitHub에서 눌리지 않기 때문이다.
- 한 항목은 한 줄. 대상 — 현상태 → 확인 순서로 쓴다.
- 번호는 문서 전체에서 이어간다. 섹션마다 1로 되돌리지 않는다.
- 대비 수치는 실제 계산값을 적는다. 어림값·추정 금지.

## 파일 위치·이름

- 디자인_docs/feedback/vN.md 또는 디자인_docs/feedback/<날짜-버전>/<이름>.md
- 과거 문서는 삭제하지 않고 누적한다.
- 상세 규칙은 디자인_docs/README.md.

## 섹션 구성 (이 순서 고정, 빈 섹션은 통째로 생략)

| 섹션 | 담는 것 |
|---|---|
| A. 오류로 보이는 것 | 값·이름이 틀렸다고 볼 근거가 있는 것 |
| B. 빠진 것 | 있어야 하는데 없는 규격·상태·토큰 |
| C. 대비 미달 | WCAG 기준 미달. 코드는 Figma 값 그대로 두고 보고만 한다 |
| D. 이름·구조 | 네이밍·계층 기준이 갈린 것 |
| E. 잘림·터치 영역 | 고정 크기·최소 터치 영역 문제 |
| F. 일관성 | 같은 역할인데 값이 다른 것 |
| 코드가 이미 맞춘 것 | 액션 불필요. 무엇이 바뀌었는지만 알림 |
| 아직 못 맞춘 것 | 맞출 토큰·규격이 없어서 멈춘 것 |
| 이전 문서에서 이어받은 항목 | 아래 승계 규칙 참고 |

위쪽일수록 오류에 가깝고 아래로 갈수록 판단이 필요한 항목이 오도록 배치한다.

## 승계 규칙 (이게 이 규격의 핵심)

새 문서를 쓸 때 이전 피드백 문서의 미해결 항목을 반드시 훑고, 마지막 섹션에 셋 중 하나로 분류해 적는다.

- 해소됨 — 이번 전달분에서 반영이 확인된 것. 이전 문서 번호를 같이 적는다.
- 그대로 — 아직 안 바뀐 것. 새 번호를 주지 말고 이전 번호로 참조한다.
- 판단 필요 — 바뀌긴 했는데 해소인지 애매한 것. 무엇이 애매한지 한 줄로 쓴다.

이 섹션이 없으면 디자이너 입장에서 "지난번 지적이 반영된 건지 무시된 건지"를 알 수 없다. 항목이 하나도 없더라도 "이전 문서 없음" 한 줄은 남긴다.

## 템플릿

```
# 디자인 피드백 vN

[출처 이름](Figma URL) · YYYY-MM-DD
한 줄 요약. 코드는 이미 맞췄고 아래는 확인이 필요한 항목이라는 점을 명시한다.
위쪽일수록 오류에 가깝고, 아래로 갈수록 판단이 필요한 항목입니다.

## A. 오류로 보이는 것

- [ ] 1. 대상 — 현상태 → 무엇을 확인해야 하는지
- [ ] 2. ...

## B. 빠진 것

- [ ] 3. ...

## 코드가 이미 맞춘 것

- 무엇을 어떻게 맞췄는지 (체크박스 없음 — 액션이 없으므로)

## 이전 문서에서 이어받은 항목

- 해소됨: v1 19, 73 — 어떻게 확인했는지
- 그대로: v1 26 — 아직 안 바뀜
```

## 작성 전 확인

- 코드를 Figma에 먼저 맞췄는가. 이 문서는 "안 맞춘 변명"이 아니라 "맞춘 뒤 남은 질문"이다.
- 값을 임의로 조정하지 않았는가. 대비가 나빠도 Figma 값을 그대로 두고 C 섹션에 적는다 (figma-bridge §3).
- 대비 수치를 실제로 계산했는가.
- 이전 문서를 훑었는가.
